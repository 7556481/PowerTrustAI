## 采用什么

复用v5精确字段诊断，原提示与严格解析不改，覆盖参考采用开发定义v2。源码基线为`3b12375bcd272dea2fc7881f76ba274486118707`；[机器清单](reviewer-independent-protocol-candidate-v1.json)保存协议/提示/11份相关源码的SHA，不能把配置文档当成新模型训练或语义修复。

对象仅为给定问题、要求、题设、证据和回答的评审组件，不评价整条RAG。程序给回答单元与位置，模型选择合法ID；程序派生composition，不代模型编造理由。完整性字段只表示覆盖，不代表正确作答或安全结论。

| 事项 | 候选规则 |
|---|---|
| 覆盖 | covered/partial/missing/uncertain：是否涉及要求及必要范围/例外；明确反向结论可覆盖，遗漏或替换必要限定仍可partial。旧met/not_met禁止自动改名 |
| 支持映射 | supported原名保留；not_supported→insufficient_evidence；insufficient_evidence/contradicted/not_assessable原名保留。未知枚举在执行前拒绝，不猜unknown含义 |
| 证据判断 | 没依据不等于矛盾；依据ID正确只表示引用身份，不证明支持正确；理由不能补全原回答缺失的例外或范围，标签/理由冲突另记 |
| 单元匹配 | 事前固定参考语义单元；等价拆分/合并可联合对齐但参考只计一次。混合支持标签、部分等价列无法对齐，冲突另列，不挑正确从句，不增加参考分母 |
| 格式与停止 | 每请求一次初始+最多一次格式纠正，无传输重试、无Revision、无自动恢复。首次执行/传输/存储/最终契约失败停止，其余项未执行；语义分歧归档不重跑 |
| 统计 | 全部计划项目/要求/参考单元均交代。分别报告覆盖混淆、支持标签、错误支持F/A_NS及F/A_SP，零分母N/A；失败/未执行/无法对齐/冲突单列，不合并综合准确率 |

这里partial指输出枚举partially_covered。映射须随未来**每个批次**的冻结清单直接绑定文件SHA，不再依赖事后查旧批。人工语义对齐仍为AI辅助、用户监督，非专家金标准；文本确认与原文件/SHA核验范围分别记录。

## 调用配置候选

deepseek-flash，https://api.deepseek.com，90秒单次、2000输出token、24000响应字符、90000消息字符；无固定温度或随机种子，采样由提供商默认值控制，漂移未知。通用规则不指定任意付费总帽：按固定的初始请求数N与每项一次纠正推导最多2N调用。逻辑预算截止采用180N秒，它是既有预算的准入截止，不声称精确墙钟强制中止；具体批次仍须显式绑定N、顺序、预算和运行入口。

所有原文、回答、预期和响应留忽略data，模型消息只含任务要求与合法输入，不含参考标签/答案角色。不能把旧12项或剩余8项入口当成任意新批次入口；选择资料及确定计划后再冻结适配门禁，复用execute/batch_control，不另建调度器。

## 已知缺陷照实保留

模型仍可能把正确性混入覆盖；识别例外缺失却判supported；理由与标签不一致；JSON语法和unit理由字段在纠正后仍失败。v5只改善诊断，不保证纠正率。此次不改提示解决这些问题，也不承诺独立评测通过。

“省略例外”的断言解释必须在新题预测前明确：究竟是不完整表述，还是无条件保证；若无法可靠消歧，事前hold并保留理由。不能根据预测再改参考，也不能假称现有开发题的争议已经消除。要求、支持性与参考语义单元须独立标注，不能借coverage的partial自动推出支持标签。
