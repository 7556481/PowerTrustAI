## 索引、中文词项与来源层级

原小库已有CJK单字/双字BM25，问题不是英文空格分词，而是查询格式词和全快照扫描。新路径为SQLite FTS5的BM25倒排查询，分片Parquet `iter_batches(128)`，精确正文SHA去重，重复原ID/分片/行号另存，批次事务保存断点。首个构建与并行发布曾遇SQLite锁升级失败，日志保留；后续批次用BEGIN IMMEDIATE和有限锁等待，从已提交行恢复。公开入口 `rag/corpus_download.py`、`rag/corpus_build.py`。

FTS5的unicode61本身没有中文语义分词。`rag/chinese_terms.py`固定jieba0.42.1、HMM关闭和小型电力术语表；正文及查询共用分词。查询v2另清理明确的回答格式要求、通用功能词，保留原查询归档；少量可审阅检索别名（无功/无功功率、功率因素/功率因数、电网/电力系统）只影响新FTS，不改原问题或全局旧库词项。条件仍完整交给生成和审核，不把检索别名当事实等价证明。术语、普通问句、同义用词与无命中输入均有离线检查；相关但不充分的材料仍会误召回，不能以词命中证明回答覆盖。

可追溯教材/官方资料优先支持其适用范围内的核验；大库正文可以扩大解释覆盖。未知原机构、URL、日期保持null，数据集链接是取得位置，不是原作者。命中Evidence绑定revision、分片SHA、原记录ID、行号、原文字符区间、正文SHA、知识版本及相邻片段；质量标记 `original_source_unverified`。不能单凭这些材料批准规范要求、设定值或工程保证。相关性与出处权威分开，没有权威加权来代替相关性。

构建/发布时FTS完整性核验、事务快照备份及流式片段根哈希；打开时结构核验、计数、只读文件身份检查。后续查询不扫描或重验全部正文，命中仍逐项核对原文/字符/哈希并确定性重放排名。冷打开核验移到启动线程，避免健康检查超过浏览器连接超时。旧库路径不变；`retrieval_mode=bm25`在带大库封印的数据库选择明确版本的FTS5路径，manifest记录真实索引/分词/查询版本。无匹配向量索引，不调用旧向量库。

## 构建、发布及日常使用

可选依赖安装 `python -m pip install -r requirements-corpus.txt`，仅CPU。恢复下载用 `python -m rag.corpus_download --manifest <已核验清单> --shards <分片目录> --output <记录目录> --proxy http://127.0.0.1:7897`。不设置持久代理或关闭TLS。

恢复构建用 `python -m rag.corpus_build --base <保留的小库> --base-knowledge <包含原文小节的版本> --database <构建库> --manifest <清单> --shards <分片目录> --wait`。已有任务仍在写时不要另起并行写者；Windows可用明确的任务进程 `--after-pid`等待其退出后再恢复，不杀进程。格式失败分片单列，不能计作完整。发布用同参数加 `--publish <新文件>`，覆盖不完整必须显式 `--allow-partial`，不可覆盖已发布文件。

本机实际路径/命令、快照与进度见忽略目录 `data/runtime_local/industry-corpus-v1/reading-notes.md`。日常双击start-powertrustai.cmd，8765自动连接；停止用项目Python `-m backend --stop --port 8765`或原终端Ctrl+C。全文、数据库、模型权重、凭据不进入Git或审阅ZIP。
