## 协议差异

| 项目 | v6改动 | 保持或限制 |
|---|---|---|
| 覆盖 | 在旧提示后明确决策顺序：找实际回应，再检查必要内容是否缺失；明确反向结论/错误关系不等于遗漏。partial必须指出真正缺少的内容、范围、条件或解释 | 覆盖字段/枚举不变；不由程序按正确性重写标签，也不自动把所有相反结论改covered；同义、合并表达及每要求独立评分保持 |
| 文献定义 | 普通陈述形式的定义/规则仍是literature_statement，对照给定文献与上下文；不要求题设前提、现场观察或实际应用核查 | 不能把真实设备状态伪装成一般定义；对象分类仍有模型语义判断成分 |
| 真实断言 | 真实设备、地点、当前测量或安全/符合性属性属于external_claim；要判supported/contradicted须选择actual_record类实例记录 | 不取消全部现场依据要求。缺记录可保留insufficient_evidence/not_assessable；文献或假定不能替代实际记录 |
| 输入依据角色 | evidence可声明source_role，默认literature；actual_record须有record_context的subject、record_id、locator，均为非空字符串。白名单model_input只传这些明确元数据，不传参考标签或理由 | 新输入元数据属独立v6版本；输出JSON模式不加冗余分类字段。记录身份是调用方提供的溯源，不是程序独立认证 |
| 解析与派生 | 先复用v5全部严格ID/结构/理由/作用域检查，再检查依据角色；派生绑定区分actual_record，支持范围明确为仅给定记录、非独立现场认证 | 原假定question-span绑定及“假定+文献规则”要求不放宽；文献定义不能以实例记录取代文献依据。program_composition仍只由判断数派生，不证明语义拆分正确 |

没有修改审核模型、生产schema、政策、检索或交付要求。没有按题号、机构、领域术语或预期标签写特殊分支；没有把缺失理由补造、替换非法ID，或自动给旧响应修分。

实际记录门禁只是必要条件：元数据合法、依据ID选中仍不证明记录真实、对象/属性匹配或安全。新提示要求模型解释同一对象与属性的对应；程序不能从自由文本机械保证这种语义匹配，也无法阻止模型把真实断言误标为literature_statement。若缺足够依据或分类不明，应保留不足/无法评估，不能由门禁通过声称现场验真。

## 不同主题的合成回归

17项新测试位于`tests/test_premise_bound_review_v6.py`，仅用合成演示索引、盘点计数、日志窗口、假定容器与试验台记录，不读取EIA/NRC回答/原始响应。

- 反向排列及错误计数运算：人工预置coverage=covered、support=contradicted，验证两维能独立解析与派生。
- 必要窗口遗漏/替换可partial，真正未涉及的要求missing，另一要求不重复降级；解析器不补内容、不改模型语义判断。
- 纯定义无假定前提/实例记录仍允许文献支持；真实状态用纯文献判支持/矛盾会被拒绝，缺依据时保留不足/无法评估。
- 合成实际记录与文献/假定身份区分、溯源字段必须完整；假定应用仍不能升级为真实现场核验，输出作用域不冒充认证。
- 输入与消息只保留任务信息，新提示确实送到模拟适配器；外来ID、额外字段、空理由仍拒绝；一次纠正耗尽后停止，不执行下一项。

连同既有v4/v5、执行门禁与白名单回归，共**51项离线通过**。合成响应是测试预置，不是模型预测；测试还特意证明错误的partial语义结果不会被解析器偷偷改covered。**离线通过不能证明模型已解决覆盖混正确性、定义对象误判、对象匹配或格式稳定性问题。** 真实改善尚未验证，本轮0付费调用，不新找保留来源。
