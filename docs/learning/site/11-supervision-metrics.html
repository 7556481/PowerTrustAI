2026-10-24 失败实验的成本与净收益

失败更早、少走修订重审可能降低调用和token，不能算效率提升。需要保留计划分母、执行完整度、各接口支持判断、正确内容误拦和初稿到最终变化。结构合法只说明合同通过；语义可靠性还需逐项依据，整体未认可不能充当每个具体错误的检出。上轮scope_v2是明确负结果，38次逐字重抄失败与合法投影误降级分开。

【教学构造】候选只完成两题，原版完成八题。候选token只有原版一半，可以说节省一半且安全性提升吗？

展开新增练习解析

不能。先报告八题计划及六题失败/未执行、逐项错误认可与误拦。若少执行、少修订造成低成本，就不是等量服务下效率收益。失败可以有诊断价值，但不构成采用证据。

2026-10-24 两条净收益线

固定回答能力线是4组原/候各一次共8分支，混入正确与部分缺据回答；自然线每题仅生成一次，共4份真实初稿，再从相同初稿/实际证据/快照分别审核修订，共8分支。材料是本轮设计与AI辅助来源审阅的开发验证，不是独立留出或专家金标准。自然生成沿当前RAG，后续成对审核固定其实际交付；生产检索默认不改。没有目标错误或没有Revision都保留，不人为改坏自然初稿或补题。

比较完整正文的纠错、漏修、新错、正确内容损失、必答点增减、合理收窄及不必要拒答；正文不变的合理核验与错误降级分开。参考支持、原始模型判断、程序有效判断和政策处置是四层，不能用pass/结构合法/发现记账替代答案质量。生成调用只计一次；两路各自扣除其已用生成预算，独立保留余量。并行与嵌套计时不直接相加，保存可见时间不是浏览器首绘，没有账单费用未知。完整分母及必要原文见本轮报告。

标签来源与质量版本

AI辅助建议、用户逐项确认、质量复核、原模型预测是不同层。confirmed表示用户按实际模板授权，不等于专家金标准。pending/hold不直接训练，建议不能覆盖复核包具体标签。任务ID、task哈希和依据子集需要逐项核对，确认事件另存，不改原pending或历史响应。

evaluation/support_training.py的confirm_template、select_materials、check_partition等维护这些约束。公开阅读权限不自动等于训练许可；AEMO材料曾按明确许可筛选，其他材料不能因已下载就进入训练。正文训练、元数据辅助和缺上下文hold分流。

为什么按家族而非随机行划分

原命题、删条件、反转数量等变体共享原证据与父谱系。随机逐行拆分，训练可见几乎相同命题，测试分数被高估。合并同概念、父关系、近重复和共享依据形成关联家族，再固定train/validation/holdout。家族划分是在模型预测前做，不根据成绩把难题移出测试。

文档留出进一步隔离另一份资料。扩大NLI用55开发、13关联家族，43训练/12验证；SSIAG33只留出，不能选模型、调参数或checkpoint。旧5题已被查看，是开发对照，不再称独立验收。即使同文档不同家族，也应报告共享正文风险，不用“随机seed固定”代替泄漏分析。

数据泄漏的几种形式

  • 输入含标签或旧模型理由：直接泄漏。
  • premise按监督basis_ids挑正确证据：给了模型标注者答案线索。
  • 同父变体跨集合：谱系泄漏。
  • 根据测试F1反复调参：选择泄漏。
  • 看留出失败后加入针对具体ID规则：事后污染。
  • 用元数据适用性写成正文：不是传统标签泄漏，却改变了可判断依据。

真实NLI适配器使用全部实际交付正文，监督basis_ids只作监督说明；正文与行政元数据分开，完整token预检，无静默截断。有效集合事前固定，基座与微调模型用同集合比较。

分类指标：先写混淆矩阵方向

三类supported/contradicted/insufficient。矩阵行是真值、列是预测。对某类TP是对角线，FP是该列其他行之和，FN是该行其他列之和。

precision = TP/(TP+FP)
recall    = TP/(TP+FN)
F1        = 2*precision*recall/(precision+recall)
macro-F1  = 三类F1的算术平均
accuracy  = 对角线之和/有效样本数
coverage  = 有效预测样本数/全部冻结样本数

当分母0时需明确实现约定，不私自移除难类。macro-F1让稀少类有同等权重，accuracy容易被多数类主导；两者都不描述工程风险成本。not_assessable不在三类NLI范围，不能把生产四分类直接当同一任务。

两个错误支持分母

教学兼真实扩大NLI矩阵见第12章。错误supported有4个、非supported真值23个、supported预测14个，则“非支持被误支持率”=4/23=17.39%；“支持预测中的错误比例”=4/14=28.57%。它们回答不同问题：前者看所有应不支持材料被误放多少，后者看每次显示supported有多少不该支持。不能互换，更不能写“准确率82.61%所以可靠”。

教学反例：33项中10项真值supported，若把33项全判supported，支持召回是10/10=100%，支持precision却只有10/33，非支持误放23/23。该构造不是实验结果，说明召回不能掩盖错误支持。真实SSIAG实验的4/23与4/14分别以非支持真值和支持预测为分母，必须并列读第12章矩阵。

检索指标与unknown

Hit@k问前k是否至少一个相关；MRR用首相关名次倒数；Recall@k需要相关全集定义；nDCG考虑分级相关和位置折扣。项目只对已标候选池Recall，不代表全语料召回。必要组覆盖要求一组成员齐全，范围完整还受原可回答性和条件充分性约束。

unknown保留实际名次，不记0，也不删除后顺延。教学构造：排名[unknown,不相关,相关]，MRR下界1/3，上界1，因为unknown可能相关。前二Hit下界0，上界1。点估计仅在明确已知覆盖时用，并报告n；不同n的均值不能直接比较收益。

验证与面试

验收应先冻结样本、预期、版本和停止条件。结构成功率、执行完成率、解决问题、语义误判及错误放行单列。无效样本不悄悄消失；覆盖低时高F1可能只来自容易项。人工评价仍写AI辅助用户监督。

练习：10条中只有8有效，7条正确，accuracy是多少？参考：有效accuracy=7/8，覆盖8/10，同时报告全批7/10的正确完成比例；不能只报87.5%而隐藏两失败。

面试可说：“我按谱系/文档留出，锁定输入与监督版本，保留unknown及分母。macro-F1提高同时误支持增加，所以没有把NLI当最终审核器。”

nDCG手算：背景相关也可能贡献，但不是直接支持

教学构造，前三等级为[1,3,0]，gain=2^grade-1，DCG=1/log₂2+7/log₂3+0/log₂4≈5.4165。理想排序[3,1,0]的IDCG=7+1/log₂3≈7.6309，nDCG≈0.7098。grade1背景也贡献1，但并不包含回答必要结论。某排序nDCG高，不代表条件和结论组合齐全。

若所有候选grade0，IDCG=0，该题nDCG没有普通比值定义，实际评测应明确约定及有效n，不随意把它计为高或低。候选池只覆盖已标材料，未标正例不凭空进入分母。项目报告对unknown更保守，某些Hit/MRR只在top5无unknown时输出点值，教学上下界不能冒充程序已有字段。

家族并集为什么会改变划分

教学构造：任务A/B同父，B/C共享同一必要条件，C/D近重复，则关联家族通过并集传递把A,B,C,D合并，即使A与D字面差很大。拆开它们可能泄漏共享模式。按家族分配会牺牲简单类别比例均衡，但保持隔离；数据量小时要同时报告实际标签分布和家族数，不能说“分层随机”就没有关联。

partition文件应保存原旧划分和新版本理由，不覆盖历史test归属；旧五题即使后来并入训练，仍说明曾被看过，不能对另一份报告重新称独立测试。监督版本和task哈希分开：相同任务可有质量版本变化，任务原文不应因改标签而悄悄变哈希。

审核产品的指标表怎么设计

结构初次成功率分母可以是所有模型审核请求，也可以是12个run，必须明确；一次格式纠正后完整执行率用全12个run。回答解决问题评价包括直接性、语言、必要条件、引用及覆盖；错误放行指实际pass的回答包含已确认阻断错误，不等于某个组件raw supported错误。

修订单独统计：自然触发数、产出新版本数、实质改正数、完整重审数、最终合理处置数。Revision API成功但漏了工程重审，不算闭环。模型把错误改成无关拒答，不算解决原问题。若未触发就写0，不捏造after表。

历史实验分母与风险措辞

0/23是support-nli-expanded-v3的官方基座在该33条SSIAG留出中、23条非支持真值里未观测到错误支持，不是零风险保证。4/23是同实验微调checkpoint的条件化误支持比例，不是所有问题、设备或工程总体风险率；4/14则是14个supported预测中错误占比。实验为单种子、单文档、小样本、AI辅助用户监督。

Tiny报告出处docs/support-finetune-v1.md：19材料、11/3/5，5条已见开发对照；MiniLM选型/首调出处docs/support-nli-v1.md：同19、11/3/5，不查看5条测试选模型；扩大版出处docs/support-nli-expanded-v3.md：43/12/33、全部有效。教学混淆矩阵算术说明指标定义，不是新增运行，也不与不同集合直接比大小。
