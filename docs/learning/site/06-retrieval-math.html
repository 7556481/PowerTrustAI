06 BM25、Dense/E5、余弦、RRF与reranker

为什么要学公式，而不是只记名称

BM25评价词项相关性，Dense评价编码空间的相似性，RRF合并名次，reranker重新比较候选文本。它们都不直接证明事实支持。懂公式能解释“为什么长正文降到后面”“为什么两路融合挤掉必要条件”，也能避免把分数包装成可信概率。

BM25的三个因素与手算

教学构造：N=4个片段，查询词voltage出现于df=4个片段，平均长度3.75。项目小库使用k1=1.5、b=0.75及正值IDF。长度是分词后token数，不是字符数。

IDF(t) = ln(1 + (N - df(t) + 0.5)/(df(t)+0.5))
score(d,Q) = Σ IDF(t) * tf(t,d)*(k1+1)
             / [tf(t,d)+k1*(1-b+b*L(d)/avgL)]

IDF=ln(1+0.5/4.5)=0.105361。D1长度3、词出现2次，TF因子=5/[2+1.5*(0.25+0.75*3/3.75)]=1.526718，得分0.160856。D2长度3、出现1次得0.115781；D3长度6、出现1次得0.082961。词频收益会饱和：出现2次不等于两倍得分；长文因长度归一受到惩罚。

小库代码查询词去重，原始分数降序；平分才按稳定文档/版本/片段身份排序。把版本字符串升序当“优先最新版”是错误，因为候选已由固定快照限定。大库FTS5的BM25实现和分值方向由corpus_index.py适配，不能拿两种原始分值直接比较质量。

Dense与E5：从token到384维向量

rag/embedding.py固定multilingual-e5-small revision 614241…，CPU ONNX、384维FP32。输入前缀query: / passage:标识任务，不改Evidence原文。模型产生batch×token×384的hidden，attention mask排除padding，做有效token均值。长passage用480 token窗口、448步长；窗口均值等权平均，最后L2归一化。query超512拒绝，不静默截断。

教学构造：两有效hidden=(2,4)、(4,4)，均值m=(3,4)，范数5，归一化u=(0.6,0.8)。padding位置即使值很大也不参与平均。另一个归一化v=(0.8,0.6)，余弦u·v=0.96。

cos(q,d) = (q·d)/(||q||₂ ||d||₂)
L2归一化后：cos(q,d) = q·d

0.96只是教学相似度，不是事实支持概率。向量索引必须绑定模型profile、维数、精度、知识版本和正文指纹；不同profile不能用同一索引。归一化次序也属于profile，因为“每窗先归一再平均”和“平均后归一”一般不等价。

RRF：为何按名次而不是分数相加

BM25的分数尺度与余弦不同，直接相加会让某路权重随语料变化。rag/semantic.py的fuse_ranks使用两路等权、常数60、名次从1开始；某路未出现的片段没有贡献，不能当rank0。

片段BM25名次Dense名次RRF
A141/61+1/64=0.032018
B211/62+1/61=0.032522
C321/63+1/62=0.032002
D431/64+1/63=0.031498

排序B,A,C,D。若答案需要B的条件和C的结论，Dense前二满足{B,C}，RRF前二却成{B,A}。A很相关但不替代C，完整组合反而退步。这是可能机制的算例，不拿它替历史模型解释内因。

Cross-encoder reranker与双塔区别

E5先独立编码q和d，文档向量可预计算；cross-encoder把(q,d)一起送模型，token间交互更充分，但每个候选都要推理。它只能重排给定池，不能召回池外材料。历史固定模型mmarco-mMiniLMv2-L12-H384-v1、int8 CPU、512 token、batch2，输出单logit，未校准为概率。

历史reranker允许候选侧右截断属于该固定实验配置，必须记录；不能把这个许可照搬到正文支持NLI。查询超长拒绝。定位/原文检查仍以未改变的Evidence为准，模型读的窗口和完整原文需要分别说明。

真实收益与退步：同时看分母

27项补标后20题开发对称回算，BM25相关Hit@5从0.75到0.90，MRR从0.6292到0.8167，但完整依据仍0.55。RRF必要组完整覆盖13/19降12/19，范围完整仍0.50。说明局部词项收益未传递到完整支持；没有因此全局开启术语扩展。

reranker固定20题，相关Hit下界1.00、直接依据Hit下界0.70，范围完整0.50→0.60，但前五仅68/100已知标签，某些点估计仅n=4。D06的必要依据组合退步，关键已标片段并非被512截断；不能把所有退步归因截断。实验未采用为默认，不等于完全无收益，也不是尚未第一次尝试reranker。该20题固定池rerank_total_seconds=180.0605494秒，来自semantic/reranker-v1/reranker-results.json；它是当时批次累计重排序墙钟，不是隔离性能基准或生成审核端到端承诺。unknown保持原名次，池外证据不能靠重排恢复。

出处是本机固定报告term-expansion-27-final-v1/report.md、reranker-v1/report-v2.md及其候选哈希；公开本章只保留汇总，不复制原文或监督明细。当前默认BM25/FTS，Dense/RRF为可选路径，reranker不是生产审核器。

练习与面试

练习：RRF里k增大有什么效果？参考：名次差带来的贡献差缩小，相对更偏向多路出现，但不保证完整依据。手算A在两路第1/50与B第10/10，比较k=1和60，不凭直觉说总更好。

面试说法：“我固定候选、知识和模型版本，分开报告相关命中、必要组合及完整依据。RRF和重排存在局部收益，也有条件段被挤出的退步，因此保持默认而没有按单一Hit值上线。”

深入实验一：两词BM25，为什么稀有条件值得保留

用教学语料D1=[voltage,control]、D2=[voltage,reactive,control]、D3=[voltage,voltage]、D4=[current]，查询voltage reactive。N=4、平均长度2。voltage的df=3，IDF=ln(1+1.5/3.5)≈0.356675；reactive的df=1，IDF=ln(1+3.5/1.5)≈1.203973。

D1长度2、voltage tf1，TF因子=1，得0.356675。D2长度3，每词tf1，分母1+1.5*(0.25+0.75*1.5)=3.0625，TF因子2.5/3.0625≈0.816327，得(0.356675+1.203973)*0.816327≈1.274。D3长度2、voltage tf2，TF因子5/3.5≈1.428571，得0.509536。D4两个词都缺，0。D2虽然长、voltage只一次，仍因稀有reactive排首。

你可以用rag.bm25.score_corpus直接复核这个纯算术例，不访问真实库。注意函数会把英文query分词去重，所以“voltage voltage reactive”与该查询相同。若把reactive换成常见背景词，排序可能不同。这个机制解释关键词与条件词的重要性，不意味着任何稀有词都应该手工加进生产查询。

DF取决于实际参与BM25统计的索引语料集合，而不是随后送入reranker的候选池。知识版本或统计集合改变可能改变DF；只裁剪/重排给定池不等于重新计算全索引DF。加入很多无关文档也可能改变平均长度和IDF。检索实验必须固定集合，才能把排序差异归因于某个处理。原小库BM25浮点值和FTS5倒排打分不能混在一个未归一的数轴做阈值。

深入实验二：窗口池化的平均次序

把实际384维缩成2维演示。窗口1均值m1=(10,0)，窗口2均值m2=(0,1)。项目采用先等权平均m=(5,0.5)，再归一化≈(0.9950,0.0995)。如果先各窗归一化再平均，得到(0.5,0.5)，再归一≈(0.7071,0.7071)。两者明显不同，所以profile必须记录归一化次序。

此外窗口重叠会使边缘token重复出现，但项目是按窗口向量等权，不声称全原文每token严格等权。长文末窗较短仍占一个窗口权重。这个实现是固定选择，有可追踪性，但没有证明它对所有长电力文档最优。更改窗口/stride/池化就改变向量profile，需新索引和独立评测。

mean pooling不是把字符向量平均。tokenizer可以把同一个电力术语分成多token，特殊token和前缀的非padding位置也参加当前均值。理解这些细节，才能解释“同一句文字换个输入前缀为什么向量变了”。

深入实验三：排名融合不是概率组合

只有一路出现的A第1名，得1/61≈0.016393；两路都第30的B得2/90≈0.022222，B反而更高。RRF鼓励多路共识，但这不是贝叶斯独立证据累积。两路可能都受同标题吸引，相关误差并不消失。

常数k=1时A=1/2，B=2/31，首名优势很强；k=60时多路出现更有优势。常数改变是排名配置，不该在看开发失败后不断调到满意。rank深度50之外视为缺失，不会偷偷使用第500名。候选深度、context数量和最终top_k是三个不同参数。

深入实验四：排序、截断和实际阅读

一个reranker的分数来自模型读到的token窗口，Evidence保留的原文却可能更长。报告应记录输入token和截断侧，不能推断模型读了全部。固定候选池外的缺资料不可能由重排序修复；候选池内有但排在第8，与完全没召回是不同失败。

教学排查表：先检查候选membership，再看前k排序；再看被截断的token包含什么；最后看必要组是否整体齐全。四层诊断能避免“一个模型更大就覆盖更好”的错误说法。历史D06必要组退步未被截断审计解释，所以保留未知的模型排序内因，不给出虚构理由。

复杂度练习：为什么大库不能每题扫原文

原小库N个片段，每题计词频与分数成本大致随总token增长；Dense暴力点积约O(Nd)，d=384，还需读向量；倒排检索成本与查询词posting和命中候选有关，不简单等于常数，但通常避免读所有正文。Cross-encoder需对M个候选逐对推理，M越大成本越高，不能把全部几百万正文送进去。

这些是复杂度解释，不是本机benchmark。实际冷打开仍有字节封印成本，热查询还有命中回查和上下文；别把索引查询毫秒数称用户端到端时间。
