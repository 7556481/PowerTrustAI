23 从SQL走到模型实际读到的证据

本专题绑定应用提交 e4fb27e7c8893a5ad141ebef0ae5f32216648065，2026-11-24离线核对。配置只看当前状态。数字分别标记真实实验与教学构造；以下问题不授权现场工程操作。

倒排索引与实际SQL

倒排索引是“词→包含该词的文档行号”的表。例如教学三段D1=电压 无功、D2=电压 电流、D3=无功 补偿，电压列表为{D1,D2}。AND交集得同时出现的段，OR并集扩大范围。项目query_expression以OR连接经过过滤、别名扩展并引用的词项；不能把用户原问题直接当未转义SQL。 大库SQL执行MATCH后按bm25(corpus_fts)、rowid排序并LIMIT；FTS5相关性值方向由适配器处理。LIMIT限制最终返回条数，不意味着引擎只处理K条命中。常见词造成大匹配集合，排序和原文回读仍可能昂贵。

题23.1：jieba、电力词典与英文分别怎样参与？

文档和查询共享terms：jieba独立Tokenizer、HMM=False，电力词赋高频；仅保留字母数字和CJK词，casefold英文。原文不被分词结果替换。查询再去格式要求、停词与扩展别名，故“同规则”不等于文档和查询每步完全相同。词典版本参与封印；若只更新查询词典而不重建对应索引，词边界变化会导致漏匹配。继续追问：OR避免全词必须出现，但可能引入大量旁证；它没有解决跨语言概念对应。

BM25、Dense、Hybrid与重排

BM25中tf是某词在段内次数，df是含词段数，L是段长度，avgL是平均长度。词频饱和、长度归一和IDF共同决定分数；第06章给完整公式、D1=0.160856的逐步演算，并区分小库正值实现与FTS5。 Dense编码成向量，余弦只度量表示接近；Hybrid用RRF合并名次，1/(60+rank)不需要两路原分可比。教学：两路名次1/3得到1/61+1/63≈0.03227；仅一路第1得0.01639。重排在候选集上比较，召回没拿到的段不能被重排救回。可选代码在semantic、reranker，不代表本机已开启。现行配置为SQLite BM25；Tantivy已退役。

题23.2：Top-K相关为何仍可能回答不了？

教学：K=3全是设备定义，但问题还要求限值和例外，必要槽只覆盖1/3。相关性排序并非集合覆盖优化。先核对原文是否在库，再核对MATCH、候选排名、根与邻接、预算裁剪、最终发送消息五层。Retriever与证据交付输出不能替代最终客户端边界的消息快照。继续追问：同ID不同版本不是可删除重复；同一请求文本相同也需保留引用绑定。

题23.3：中文查询为什么找不到英文原文？翻译有何风险？

词面索引不自动认识中文概念和英文词的等价关系。历史跨语言候选改善目标交付，却把日常“投入退出”改成投运退役；有效JSON并未防住换义。比较必须保持来源范围一致，否则缩库和查询转换混杂。见跨语言报告。实际采用需要忠实性及最终回答验证，不能按已知题号路由。继续追问：邻接保全条件仍可能被生成模型删去，所以必须再核对模型输出。
