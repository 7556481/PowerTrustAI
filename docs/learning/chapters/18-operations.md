## 最小复现先隔离接口，再检查业务



【真实观察】本轮四种短合成Schema分别走直接HTTP与项目适配器，实际正文逐字节相同，八项都合法。之后旧业务回归出现嵌套conditions额外字段及来源ID错误，只有两项执行完整。没有发现客户端差异，也不能因此认定服务端严格约束始终生效；未知内部原因应保留。[证据与版本](https://github.com/7556481/PowerTrustAI/blob/1a92d03da49ae25f311e950373003d6ab32d09f5/docs/evaluation/strict-interface-consistency-v1/report.md#)。



诊断应记录真正交给连接的URL、参数和正文身份，以及接收时arguments与解析后字符串是否相同。只比较构造函数不能排除后续改写。Schema约束对象形状，业务还要检查ID是否属于当前来源目录、条件归属和引用范围。结构合法的S1B0也可能不是要求的SRC:S1B0；程序不能替模型换成正确ID。



【教学构造】两条客户端发送字节完全一致，都通过四种合成输入；复杂业务却多出Schema禁止字段。可以断言适配器导致错误，或把字段删掉继续吗？



::: answer 展开最小复现练习解析

不能。相同发送字节削弱了客户端构造差异这一解释，但无法观察提供商内部处理；少量成功也不是总体保证。应定位首次违例位置、保留参数与Schema身份、本地拒绝额外字段。删除字段会掩盖原输出失效。结构故障与语义分歧分别报告，不用随机差异证明客户端因果，也不以新提示重跑凑成功。

:::



## 上一严格载体批次的停止与回退



【真实失败】实际API未拒绝请求，但参数严格解析失败，唯一纠正后仍未完成；按A1/A3准入规则封存，不换参数、接口或模型试到成功。原始调用ID、参数、结束、用量和本地关联可回查；不能自动去重或剥离多余括号。本轮没有合法结果，不继续服务验收；生产默认JSON不变。[实际证据](https://github.com/7556481/PowerTrustAI/blob/1a92d03da49ae25f311e950373003d6ab32d09f5/docs/evaluation/strict-review-tool-v1/report.md#)。



## Beta与显式回退



strict_tool_v1由服务端开发配置显式启用，只作用于simple_v1事实/引用审核，走官方Beta且非思考；生成、领域和修订继续原路径。回退为review_result_transport=json，生产从未自动切换。实际Schema被拒绝时必须停，不在付费中自动试另一个接口或参数。



【教学构造】冻结后的严格工具请求收到HTTP400，是否可以同运行切回JSON模式把剩余题跑完？



::: answer 展开Beta回退练习解析

不可以。那会改变冻结的实验条件，也可能绕过共享故障停止。应保存安全状态/类型/关联及诊断缺口，停止后续发送，保留已受理结果。回退是显式配置行为，不是失败后的隐式重试；不得把新诊断反推成旧请求的确切原因。

:::



## 实际接入没有完成时



【真实失败】v9.22.1三次实际消息均通过JSON模式检查并有返回，没有请求拒绝；原引用输出重复键，唯一纠正仍失败，正式A1接入门禁停止后续26槽。不要改用“最后一个同名字段”为准，也不要把部分合法事实变成整答通过。本批没有实际HTTP拒绝，相关故障状态只由离线替身验证；停止后不另发付费探测。[原文及版本边界](https://github.com/7556481/PowerTrustAI/blob/1a92d03da49ae25f311e950373003d6ab32d09f5/docs/evaluation/review-simple-patch-v1/report.md#)。



## 公共请求边界：额度、故障与纠正



请求预算的额度与运行是否还能发送是两个问题。JSON模式必须检查实际消息，而不是只看提示常量；初始、纠正和引用请求都应经过同一入口。请求被服务端拒绝与模型返回了不合法结构不同：前者要封住同运行的后续组和下游请求，后者按原有限纠正处理。已经进入网络的并行请求不能说成没有发出，返回仍需保存。



错误诊断也需要边界：记录有界HTTP状态、白名单类型和安全说明；可能回显私有输入的原始错误消息不落盘，省略时明确记诊断缺口。服务端关联ID可存哈希，本地关联ID用于追踪；新诊断不能反推旧请求的确切状态。



【离线教学构造】两次失败分别是HTTP422拒绝，以及HTTP200返回的JSON缺少必需字段。都还有预算时，是否都能继续一次纠正？



::: answer 展开公共边界练习解析

不能。HTTP422是请求级故障，本运行后续引用、纠正和下游模型都应停止，批次也按共享故障规则停止。HTTP200的结构失败可以使用原有有限纠正额度；不能因为有余额就重试被拒绝的请求，也不能把已接受结果丢掉。这里是离线行为检查，不是故意付费制造故障。

:::



历史观测（2026-10-23）：剩余五项固定服务验收完成，本机受管默认已为langgraph_v1，正常服务ready；无配置源码fallback仍sequential。新批32调用、413018token、0失败/未执行；两项诊断实际一次修订和完整重审，但图最终待补充保留，不冒称全部答案认可。四Agent、schema13、七共享阶段及预算/政策不变，A/B未采用。历史104运行/2278事件/2999版本证据对象/8反馈及SHA启动前后相同；原编排可正常停服改受管配置回退。工具浏览器入口已验、登录后视图待一次用户清单，不绕本地文件限制。详见[后续验收](https://github.com/7556481/PowerTrustAI/blob/1a92d03da49ae25f311e950373003d6ab32d09f5/docs/evaluation/langgraph-service-continuation-v1/results-v1.md#)。下文2026-10-22及更早状态保留历史含义，该补记仅表示2026-10-23的观察，现行配置请读状态页。

## 迁移需要证明什么



先定位实际迁移目录，核对restore、manifest、exclusions、failures；大小/SHA相符再复制data，相对结构不变，冲突停止覆盖。数据库检查SQLite integrity，保留迁移目录，不复制旧虚拟环境、旧凭据或旧WAL/SHM。模型revision/配置/快照与索引需匹配。



路径变化只修改新的启动配置和环境，不批量改写历史冻结请求、task哈希或归档。旧训练环境重装依赖不等于重跑实验；恢复验证仅导入/本地加载。凭据由所有者本机填写，报告仅路径和版本，不显示真实值。



## Git与命令级网络



修改前看status、HEAD和远端，实际有更新接续不回退。代码/Markdown/静态站源码提交，data/原始响应/权重/官方全文不提交。普通push，不强推。代理只在明确需要的Git命令使用已核实127.0.0.1:7897，不能把Git代理盲套到模型API，更不关SSL。



```powershell

git status --short

git rev-parse HEAD

git -c http.proxy=http://127.0.0.1:7897 ls-remote origin refs/heads/master

```



本地提交成功不等远端更新，push之后读远端哈希；敏感检查应看实际Git树和blob，不只相信.gitignore。配置说明用空值或名称，不含密钥。



## 按错误层次排障



| 表现 | 应查证据 | 不要做 |

|---|---|---|

| 401/连接丢失 | 本机会话、固定令牌路径、origin、服务重启 | 发令牌到聊天或URL |

| 422输入拒绝 | 必填字段/模式/长度及实际请求 | 编造厂站参数 |

| 429队列满 | 活动run及等待队列 | 连续POST刷提交 |

| 模型连接失败 | 实际异常类型、阶段、服务配置 | 认定不支持中文、关闭SSL |

| OUTPUT_CONTRACT_ERROR | 原响应、纠正、具体字段、实际模板 | 只补题目提示、静默填ID |

| 证据不足 | 原文、范围、交付、完整命题条件 | 把未找到说成全库不存在 |

| KeyError _id | 分片schema与原断点 | 重复下载或清空库 |

| interrupted | 原结果/阶段、重启恢复 | 自动重发付费任务 |

## 构建与进度排障



先查实际命令/父子关系、日志尾、next_row、磁盘，再判断退出原因。没有日志证据就写未知，不猜断电/网络。仍有唯一写者时不另起；退出后从有效断点恢复，不能清库。发布有独立完成核验记录后才可考虑切换日常配置，此为历史阶段；2026-10-08经过独立装配、索引回查及空闲正常停服后，日常显式切换完整发布。



## 面试与最终练习



练习：日常服务正常、学习站8770打不开，是否要重启审核？参考：不需要，查学习server/静态文件/端口，不干扰8765。练习：模型API成功但Git推不上，是否统一设置全局代理？参考：分别诊断，保持命令级及SSL。

## 文档源码跨平台身份



Git可把Windows工作区CRLF检出为Linux LF；直接比较工作区原字节SHA会误报代码不同。学习站source-check同时保留原始文件SHA和明确source_text_lf_sha256（仅CRLF→LF，空格/代码不变）；CI按后者核查教学源码。真实Evidence、PDF和快照仍严格原字节/原文/版本哈希，不能套这个教学规则修改生产依据。首次远端CI失败保留，Git LF副本重现后修复，再核对CI，而不是取消来源校验。
