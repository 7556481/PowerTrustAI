# 35 Overlap：从任务创建推导终态时间

当前受管配置见[当前状态](../../current-status.md)。实际[发布记录](../../maintenance/local-overlap-release-v25.md)链接固定v23配对报告。以下秒数全部为教学时间线，不能当生产测量。

## 旧流程里真正的空等
旧流程先准备事实输入，再读取领域材料，随后事实/领域模型并发。事实明明已有足够输入，却仍等领域读取结束。新流程在事实输入冻结后create_task，随后领域读取；review_pair接住早期事实task，与领域角色汇合。事实内部仍serial_v1，生成/修订、资格、模型与审核合同不变。

定义F为事实材料齐备时刻，R为领域读取耗时，V为事实模型总耗时（含内部纠正），D为领域模型总耗时。先假定资源互不竞争、提前事实不改变R/D/V、任务会及时得到调度、两路均完整且没有额外修订。
```text
旧：F ──领域读取R──┬──事实V──┐
                  └──领域D──┴─汇合
新：F ──事实V───────────────┐
     └──领域读取R──领域D────┴─汇合
旧终态 = F + R + max(V, D)
新终态 = F + max(V, R + D)
```
汇合后若还有保存、修订或新版重审，应继续接在这条依赖图上；此公式只描述本轮双审边界。不能把首稿后的公式宣传成点击到首稿的提速。

## 四种时间线逐步演算
|情形|输入与假设|旧的结束时刻|新的结束时刻|终态差|
|---|---|---|---|---|
|事实是关键路径|F=2，R=4，V=10，D=5，时长不变|事实16，领域11，取16|事实12，领域11，取12|提前4|
|领域是关键路径且其他不变|F=2，R=4，V=6，D=9|事实12，领域15，取15|事实8，领域15，取15|0|
|候选多一次模型纠正|第一行旧V=10，新V=16，其他不变|16|事实18，领域11，取18|反而晚2|
|共享资源竞争|第二行旧结束12/15，新事实8，但领域受竞争延到17|15|取max(8,17)=17|反而晚2|

第三行不是“调度必然改变模型纠正”的因果证明，只示范真实对照若发生纠正差异，应如何计算实际等待。第四行可来自线程/CPU/磁盘或服务限流竞争，必须有同run记录才能判归因，不能由一个慢样本猜原因。

“领域原本最后完成”本身不推出无收益或不退化。只有新领域结束仍相同、事实也没有越过它、无后续路径改变等假设成立，才能得到第二行的0。若提前请求改变资源竞争，必须用新的实测结束时刻重新取max；不允许继续套“最大省R”的理想公式。

## create_task、HTTP线程与汇合是三个时刻
`asyncio.create_task`只是让协程进入可调度状态。若随后同步SQL占住事件循环，协程要等SQL结束才执行；因此不能以create_task日志证明overlap。模型适配器执行到_executor.submit后，线程开始_work/_http才是真正网络工作的起点。review_pair的gather则是等待角色结果，不是再次发送事实请求。

正式轨迹至少应有事实HTTP工作线程启动、领域读取开始/结束、两个角色完成、答案可读取时刻。对同一次run按answer_version关联，不能拿另一题的HTTP时刻拼时间线。检索/模型/纠正耗时按并行区间画出，不相加。测试见[test_fact_domain_overlap_v23](../../../tests/test_fact_domain_overlap_v23.py)。

## 失败和资源归属不能为提速牺牲
领域读取失败会cancel早期task并gather收尾，RunExecution不能标双审完整；底层HTTP可能继续，Bundle.drain等待后才释放。预算不足时可能不准提前，不能为了演示重叠新增调用预算。普通Factory仍是显式回退路径，不偷偷改变政策。

v23七个完整同初稿真实Flash对的首稿后审核终态中位33.48→23.71秒，证明该批的等待减少约9.8秒；不证明首稿更快。固定报告与发布验证分别覆盖配对收益和隔离烟测/配置，不把“配置已启用”当所有自然任务都已观察到重叠。

::: answer 题35.1：旧事实12、领域15，新事实8、新领域未知，能否填节省0？
不能。若保持领域结束15，max从15到15，才是0；若竞争使其17，则晚2。必须先找领域结束和后续保存等时刻。未知不能填原时刻，理论不变假设应显式写在估算旁。继续追问：若只有服务端已保存时间，就说已保存，不称浏览器已看到。
:::

::: answer 题35.2：第一行若汇合后新版修订与重审额外18秒且两路相同，省多少？
旧16+18=34，新12+18=30，仍省4秒，但相对比例4/34≈11.8%，达不到15%。同一个局部改动可能绝对秒数不变、整链相对收益下降。若两路修订结果不同，18秒不再是共享常数，应逐路按实际轨迹计算；不能把表内局部改善直接当发布门槛通过。
:::
