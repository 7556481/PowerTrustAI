# 21 从用户问题到可交付对象

本专题绑定应用提交 `e4fb27e7c8893a5ad141ebef0ae5f32216648065`，2026-11-24离线核对。配置只看[当前状态](../../current-status.md)。数字分别标记真实实验与教学构造；以下问题不授权现场工程操作。

## 前置：四个容易混同的对象
回答是保存的正文；审核意见是对某一版本的判断；修订是被授权后产生的新正文；执行状态说明程序是否完成必需步骤。它们可以分别成功或失败。一个已保存的初稿可能仍在审核，也可能因超时永远只有部分审核。
“合同”是程序接受输入输出必须满足的约束，不是模型事实正确的保证。[数据对象](../../../core/models.py)使用不可变dataclass；边界另由[校验器](../../../core/validation.py)检查。字段有类型也不代表一个句子符合事实。

## 三类问题的证据门槛
概念解释需要定义、因果与适用条件；文献解释还要绑定指定版本、原句和上下文；现场判断需要设备、网络、运行方式与测量输入。文献中的一般规则不能替代现场参数。用户假设应作为假设保留，不能伪装成检索来的事实。资料未给出时，应说明缺什么，不能用另一机构的相似规则直接补齐。

::: answer 题21.1：有引用但没有现场短路容量，为什么不能给出补偿装置投切方案？
直接回答：引用可以支持方法，不能证明现场满足方法的前提。判断顺序是识别任务要求、区分假设与实际输入、检查必要资料。项目中[领域审核](../../../agents/power_domain_review.py)与[任务义务](../../../services/claim_obligations.py)承担工程条件检查；具体缺项要沿任务规则读，不能由本教学例添加生产规则。若没有运行数据，只能给原理解释或待补资料。常见误答是“检索到了标准，所以工程结论有效”；检索相关性没有验证工况。继续追问：若用户明确假定短路容量足够，回答应限定在假设下，仍不能称已现场核实。
:::

## 处置怎样产生
[RunExecution.merge_and_decide](../../../harness/execution.py)汇总事实与领域输出，再调用政策。政策检查执行问题、审核发现、依据和修订额度，并不按两个Agent投票。不同配置可能使用不同政策；需先读Factory的实际装配，再读[基础政策](../../../harness/policy.py)与[产品政策](../../../harness/product_policy.py)。不能把一个历史pass样本推为所有配置的门槛。

::: answer 题21.2：资料不足与执行失败如何区分，pass能否叫安全认证？
资料不足是证据或必要输入不够；执行失败是超时、非法输出或存储等步骤没有完成。应分别查看审核语义状态、execution_issues与运行状态，不能只看正文是否存在。合法无实质回答还有专门不适用路径，见[生命周期章节](10-api-storage.md)。pass是给定合同和政策下的程序处置，模型可能漏错，不能叫工程安全认证。验证应同时构造缺资料和接口失败两个反例。继续追问：如果两个错误状态同时存在，应保留执行问题，不能把它降格为纯资料不足。
:::

::: answer 题21.3：为什么“建议补条件”不直接授权改正文？
意见可能只指出不确定性，未给可支持的新句子；也可能质疑提取是否忠实而没有证明原回答有错。改稿还需要符合资格、有绑定的发现与依据、剩余额度，并保护已正确内容。[修订资格](../../../services/bounded_repair.py)与[修订Agent](../../../agents/revision.py)分别处理入口约束与输出。未知应保留，不能靠改弱所有句子制造通过。继续追问：给定成立发现后的修订成功，只验证后半条链，不能证明系统能自行发现同类错误。
:::
