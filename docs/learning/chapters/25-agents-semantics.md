# 25 主张、支持关系与修订权限

本专题绑定应用提交 `e4fb27e7c8893a5ad141ebef0ae5f32216648065`，2026-11-24离线核对。配置只看[当前状态](../../current-status.md)。数字分别标记真实实验与教学构造；以下问题不授权现场工程操作。

## 数据先于角色名
生成消费问题与交付证据，输出有版本的正文及引用；提取服务消费该正文，输出主张与覆盖信息；事实审核消费原句、主张、独立证据和原引用，检查支持关系；领域审核看任务、工程前提、工具结果和领域证据；修订消费授权发现及允许依据。入口分别在[生成](../../../agents/generation.py)、[提取](../../../services/claim_extractor.py)、[事实](../../../agents/evidence_verification.py)、[领域](../../../agents/power_domain_review.py)、[修订](../../../agents/revision.py)。

::: answer 题25.1：一句话两个事实怎样提取，覆盖为何不等于忠实？
教学“设备A在恒压下提供无功，且能适应任意频率”含至少两个可核查断言。拆分应保留各自条件、量词、否定、单位与指代主体，不能把第一个分句的条件误挂第二句。覆盖只说明原句范围被提取，不说明主张没有改义。例如把“常见”提为“最典型”仍可能覆盖整句。定位、覆盖与语义忠实分开核验，见[review_fidelity](../../../services/review_fidelity.py)。继续追问：原文中的when被提成only时，必须先处理提取失真，不能用失真命题替原句做事实结论。
:::

::: answer 题25.2：不足、矛盾、无法评估与不适用如何区分？
不足是未取得支持或反证的充分材料；矛盾需要有效反证，不能由没找到推出；无法评估可能是主张或语义作用域不清；不适用说明该类检查没有核验对象。具体枚举以相应输出合同为准，不可把领域和事实协议字段互换。项目[test_fact_retrieval](../../../tests/test_fact_retrieval_v1.py)验证交付，语义仍需人工/AI辅助复核。继续追问：两个角色都“支持”仍可能共同漏错，投票不会修复共同盲点。
:::

## 多意见与修改责任
同句可能同时有事实、引用、工程前提意见。程序保留各自身份、理由和定位，不能按票数抵消。审核冲突交政策形成处置或保留待复核，并无“多数决事实”。“重要→必须”“when→only”是义务强度与排他条件改变，模型可能只看主题相似而认可，因此程序的ID与字段守卫不足以证明正确。

::: answer 题25.3：modified、retained、unresolved如何核验？
这些处置是修订合同的记账，不是程序自动理解改稿结果。需核对授权项集合、允许引用、正文范围和版本，再比较实际文本是否改了对应问题、保留正确内容。生产revision合同与历史local_revision_v2候选有差异，后者的source actions不能当通用默认。见[合同](../../../agents/revision_contract_v2.py)、[局部修订候选](../../../services/local_revision_v2.py)。无修改不能冒称修复成功。继续追问：修订稿产生新断言，旧主张/旧审核不能覆盖它，所以必须重新提取和完整双审，而非只检查改动句。
:::
