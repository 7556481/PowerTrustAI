# 17 深入面试、公式和代码练习

配置、启动与能力边界见[当前状态](../../current-status.md)。先按[最终机制正文](../resume-learning-map.md)学习输入、状态、异常与验证；本章保留基础推导。历史实验不参与正式流程选择。

## 当前面试介绍（唯一主入口）

PowerTrustAI根据电力资料回答问题，保存带引用的初稿，再提取主张，分别做事实与领域审核。事实审核检查原文支持及限定，领域审核检查工况、适用条件与必要输入。LangGraph路由已有业务阶段，Harness管预算、超时和取消。有明确修改依据且符合资格时最多修订一次，新版重新提取并完整双审；SQLite保存每版正文、证据和审核记录。

本机受管配置使用SQLite FTS5/BM25、schema13和云端DeepSeek Flash，启用事实审核与领域检索重叠；通用配置与历史候选不能混说。上述是项目机制介绍，个人负责哪些步骤由本人确认，不预写个人贡献。

## 沿三次追问展开

接口怎么接：[24章](24-model-wire.md)从ModelRequest到HTTP再到业务parser。为什么分两种审核：[25章](25-agents-semantics.md)比较输入、义务与证据。为何有时变快：[35章](35-case-overlap.md)算两条依赖路径及资源竞争，不能只说用了并发。

::: answer 对象推演：v1改成v2后，能保留哪部分？
历史v1正文、引用和审核仍保存；不能把v1主张和通过结论贴到v2。新版须重提取、双审，再保存对应版本报告。没改正文只给意见，也不能说已经纠错。按[31章](31-case-revision.md)D/O示例逐项写出版本与动作归属。
:::

## 效果如何陈述

正式十题六题完整审核，该批没有有据修订；历史给定发现四例修订成功不等于自主发现收益。v23七完整同初稿对照33.48→23.71秒，起点是首稿交审核；Tantivy最终产品比较更慢且已退役。数字对应[性能正文](16-performance.md)及固定报告，不相乘，不包装工程安全认证。
