# 短概念问答：证据约束生成的一轮改动方案

2026-10-22。基于提交 `01f4d10cab2ca2fd8bbec037ae75b2074633c650` 的只读代码核对。用户提出优先优化生成侧证据使用，本记录将其收敛为待实施方案；本轮没有修改提示、代码、检索配置或生产，也没有调用模型。

## 要解决的业务行为

答案直接好懂，资料支持到哪里就写到哪里，必要条件出现在实际答案中；审核能指出具体原句的问题。首轮只研究短概念问答的生成，不同时改修订、审核、用户界面或LangGraph路径。工程方案、现场诊断及操作建议暂不纳入本候选适用范围，不能凭关键词把混合任务强行划为概念题。

用户提出的五项方向均保留：理解问题、按所需关系取得证据、简洁组织答案、可靠局部修订、分开展示执行与审核状态。后两项属于后续独立改动，本轮不承诺自动修复或界面交付。

## 现有实现与实际缺口

- [生成器](../agents/generation.py)的 `messages_for` 已要求保留条件、因果方向、区分定义与特例、只回答问题；`product_guidance` 中还有较多具体提示。继续堆叠说明未必解决实际执行问题。
- [GenerationInput](../agents/contracts.py)已承载问题、回答要求、证据及来源绑定；目前没有专门承载必答点与证据关系的结构。`evidence_sufficient` 是生成自报，不是程序确认支持成立。
- [共享阶段](../harness/execution.py)的 `generate` 先按生成用途检索，再交付全部输入证据；生成快照校验要求保留实际交付的全部证据与知识版本。引用ID与定位通过，不证明引用支持语义。
- `prepare_review` 已按事实、领域用途分别检索；实际回答经过提取，审核输入还包含生成快照。应保留这些边界，不能用生成自列的要求或选中依据替代审核范围。
- [生产组装](../backend/assembly.py)当前使用生成schema3及既有产品提示，事实审核沿用schema13；独立v7评审组件不是这里的生产生成器或审核器。

这些是代码事实，不能据此声称每项业务缺陷都已在当前生产版本复现。历史失败可作开发检查材料，不冒称新的独立验证。

## 候选生成方式

候选另立版本，通过开发入口选择；现行生成版本与默认路径保留。优先在一次生成请求内完成问题理解、依据核对与成文，不为规划额外增加一次模型调用，也不新增调度器。

1. 从原问题及显式要求提取少量必答点，保留对应问题原文、适用范围及必要条件。区分定义、关系解释、比较等需求；不得自行增设现场核验或性能证明义务。
2. 为各点建立诊断映射：输入依据ID、精确原文定位、原文实际支持的关系、条件，以及未支持的部分。区分“术语出现”与“解释了所问关系”；相关公式也不能自动充当因果解释。映射中的语义判断仍需复核，不能命名为已验证事实。
3. 先给直接答案，随后只保留必要条件和具体缺口。部分有据时回答有据部分并说明剩余问题；不能为减少无据附加而删掉用户子问题。题设假定与文献事实分开。
4. 返回实际答案及诊断映射。映射作为候选专用诊断旁录，不作为答案引用、审核标签、政策输入或用户可见推理过程；只记录简短可核对的依据说明。实施时另立严格候选输出契约并记录版本，程序核对ID、位置及字段，不自动补造映射，不把合法定位当语义支持。

生成快照继续保存完整实际交付证据，不能只保存选中子集。候选映射不传入审核作为真值；审核仍接收原问题、原要求、实际全文及现有证据输入，检查包括意外新增的断言。生成漏列的必答点不能从审核义务中消失。

## 第一轮怎样比较

先固定问题、显式要求、题设、完整交付证据与版本，再比较现行生成和候选生成；首轮不改变查询、知识快照、检索设置、审核器、政策或编排默认。这样先检查“资料已经交付时能否用好”，不把检索变化混入生成收益。按关系检索留作后续单独比较，当前不增加知识库或模型查询规划服务。

固定题从已登记开发材料中选择，覆盖：定义直接有据、关系只有相关词而无解释、带必要条件的解释、多子问题部分有据、无关数字或保证的诱惑、题设与文献联合应用。现有24份固定回答的组件基线不能直接替代生成任务；若使用其来源改进生成协议，应登记为后续开发用途并保留原冻结成绩。题目和用户侧评分要求先固定，不能以候选自己列出的必答点作为评分分母。

不新增百分比验收门槛，不合并总准确率。逐题保留答案与依据，分开记录：

| 观察项 | 记录方法 |
| --- | --- |
| 直接回答 | 必答点是否明确回应，是否被无关背景或泛泛限制替代；明确说错仍可能覆盖，支持错误另记 |
| 条件保留 | 每个适用条件是否在相关实际句子中保留、遗漏或说反，不用旁录代替答案 |
| 无据附加 | 逐句标出无据因果、数字、保证、范围扩大及其位置，不以少写或拒答自动记改善 |
| 审核表现 | 逐项报告审核是否完成及具体问题是否被发现；流程完成、政策通过和人工认为正确分别记录 |
| 执行和开销 | 首次／最终结构有效、纠正、失败、未执行、调用与token、生成及全链路耗时分别报告 |

审核完成率须同时交代全部计划任务、产生实质回答任务、实际进入审核任务的数量；拒答后的“不适用”不能计为审核完成。人工判读记录AI辅助、用户监督；更易读的评价保留具体原文及原因，不虚构客观量表。

离线阶段用替身响应检查候选契约、消息白名单、完整快照及审核输入独立性；不能用替身或旧响应回放证明新生成的语义改善。未来真实比较另行冻结材料、模型与采样、交错顺序、消息身份、调用预算、纠正与超时停止规则，并取得新的费用授权；不沿用历史批次授权，也不补跑到满意。

## 当前停点

本轮交付为一份集中方案，未启动候选实现或题目制作。下一项可实施工作是开发用候选生成器及离线接线检查，随后才准备真实比较。局部修订、审核器优化、按关系检索、界面状态改进分别留待有明确证据与范围后决定；不因已安装LangGraph而增加自主工具调用。
