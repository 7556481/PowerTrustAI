## writer为什么失败：已缩小，尚未确定根因

v1末次失败在committed=48000、attempted=48002；主异常为writer killed，清理wait返回worker failed。224MiB只是Python每1000条检查的软限制，不是Windows Job或硬内存限额；失败回执RSS约87MiB，不能据此归因为224MiB不足。v1使用subprocess.run等待子进程结束后再开下一writer，代码未发现同目录多writer并发；这不是对历史OS锁/瞬态I/O的完整证明。

[官方0.27核心代码](https://github.com/quickwit-oss/tantivy/blob/0.27.0/src/indexer/index_writer.rs#L329)表明wait_merging_threads把worker返回Err映射成通用错误；prepare_commit的join则传播原始Err。旧清理顺序因此丢失了进一步区分I/O/其他worker错误的机会。新错误路径先尝试commit捕获原错误，再记录join；合成测试验证错误不会被通用join覆盖，不宣称已重现真实根因。

同版0.27.0固定失败位置窗口[48000,49000)，保留完整stderr、异常链和退出码。D1只复制v1的派生Tantivy索引到新目录，原库、v1索引均不写入：

|D2|相同输入、32MB，换全新目录|1000条一次成功|
|D3|相对D2仅改128MB writer|1000条一次成功|
|D4|相对D3仅改每100条正常commit/wait后重开|1000条一次成功|
|D5/D6|预留有依据的绑定验证/诊断|未运行；没有凑满矩阵、自动重试或换版本|

输入、既有提交状态、短窗口反复重开均未单独复现错误。历史长运行/进程重开与分词交错、瞬态I/O/锁和系统压力尚不能排除，也没有证据指认安全软件或Tantivy本身不稳定。新诊断均exit0，stderr为空，未取得Rust panic栈；RUST_BACKTRACE=full及faulthandler已设置，但普通Err未必产生栈。精确ModuleName=tantivy.pyd的Windows Application Error/1000查询无匹配事件，不等于不存在已捕获的原生错误。未改全局系统配置或安全软件。

## 统一实现与资源

先把同样的预分词串写入派生spool，再用一个长生命周期writer建库；分词、读源与writer不再长期交错。Tantivy0.27.0、psutil7.0.0；writer heap128,000,000字节，索引worker1，CPU亲和0/1，子进程BelowNormal。未关闭merge、未调BM25、未改变分词与查询。原生merge池默认4，由当前Python接口无法独立配置；索引worker=1不等于总原生线程≤2，CPU亲和只约束可用核心。实际线程数和进程树均保留监测。

开始可用内存1,691,947,008字节；冻结进程树上限512MiB，低于其一半且低于1GiB。树RSS及private commit均计入，并含父进程、venv启动器和全部递归子进程，每100ms采样；系统available、commit与服务任务状态同时监测。源库、预分词和query不复制成另一套来源。派生/临时总量≤30GiB，磁盘保留≥30GiB，整个计划从开始计时≤4小时，包含诊断、准备与复核等待，不重置计时器。服务有任务或内存压力时正常commit安全点暂停；不杀用户进程。

异常或资源停止后保留失败，不自动续写失败索引。v1旧48k只用于诊断副本及readonly逐项比对，正式两份50k都从零构建。全部前48k的fragment_id/body_sha/terms_sha与v1逐项一致。

## 测量口径与质量边界

沿v1同一仿射嵌套成员与12条冻结原查询，包括S5/S8；原表达式和转换树保存在忽略的freeze文件，不换题。674文献集合另外从零构建，不混入随机样本。两后端同一terms字段、同一预分词串，K3，每题各3次，顺序B/T、T/B、B/T。首次为建库后的首次观测，不称冷盘，不清OS缓存。计数另外各一次，不加入普通Top-K。

分别记录compile、内核、原文回查、邻接回查。原文经现有KnowledgeStore/corpus_evidence读取，校验ID、版本与hash；邻接使用原ContextOptions(2400,6,1)。额外语义成员断言及邻接二次校验不塞入普通回查计时。全文件来源封印单列，一进程只做一次原SHA256，后续复用既有_OPENED；增加分块暂停检查，没有跳过身份验证。

FTS Unicode61与Tantivy whitespace复用同样预分词；BM25名字相同不等价，IDF、fieldnorm量化、浮点评分及并列地址顺序不同。SQLite以score,rowid稳定排序，Tantivy保留自身DocAddress tie规则。命中数相同只支持本12条的匹配计数一致，不证明完整集合或泛化语义等价。全量ID验收的all_query(n)是独立验收而非普通Top-K，实际会物化n个命中，不能称流式扫描或用它评判Top-K性能。

两路共同偏题或必要原文不在样本，单独记为共同不足；来源可查、非空与支持主张分开。人工差异复核为AI辅助、用户监督的开发复核，不是专家金标准。正式计时实现冻结后未调参数追成绩。
