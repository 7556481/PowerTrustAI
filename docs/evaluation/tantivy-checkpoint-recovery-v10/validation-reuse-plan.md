## 建议的单一复用方案：控制器持有不可变输入身份

1. 下一版本在控制器准入时完整验证源库、sidecar和完整spool一次，登记文件系统身份、源知识/分词/schema/代码版本、精确成员数和完整摘要；不只凭size/mtime缓存通过。
2. 在该控制器生命周期中，以只读、阻止正常写入和替换的受控文件句柄固定源库及spool。只用于这两份不可变输入，绝不能给Tantivy的.managed或merge文件加禁止删除句柄。需先测试SQLite只读连接与Windows共享模式兼容性，spool读取入口必须显式mode=ro，不再执行建表DDL。
3. 新writer通过现有受监管入口取得控制器的活跃验证epoch；核对控制器PID/创建时间、固定句柄对应的卷/文件ID、路径/manifest与原摘要。控制器/句柄丢失、源/sidecar变更、epoch不匹配即拒绝或重新完整验证。控制器重启不能仅凭落盘成功回执跳过SHA；正常文件不可变性无法证明时保持现状，不降低身份要求。
4. 每次故障恢复仍检查动态checkpoint、mapping、journal精确边界、全部原生ID以及必要原生文件CRC。meta/.managed和新merge文件会变化，不能套用不可变源库证书。读取相关输入前缀与pending做一致性核验，不再扫描尚未建到的所有spool行。
5. 已原生提交的journal批次只更新映射，不重放；当前恢复次数、零进度停止和原预算不变。最终新进程全量身份验收保留，不用控制器证书替代发布验收。

预计可避免每次worker重启的不可变源/全spool重复读取，但当前没有子项计时，不能承诺节省37分钟。动态前缀/ID/CRC仍随索引规模增长；本方案不保证恢复成本恒定。
