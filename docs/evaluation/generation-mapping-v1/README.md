# A：最小可选生成映射候选与离线接线交付

## 实现与开发入口

新增 [generation_mapping_v1.py](../../../agents/generation_mapping_v1.py)，版本 `concept-evidence-generation-map-v1-dev`，响应契约 `generation-answer-and-map-v1`；原 [generation.py](../../../agents/generation.py)、schema3解析、四Agent公共契约及生产工厂均未修改。没有改检索、审核器、修订、政策、UI、依赖或LangGraph路径。

开发时显式构造 `EvidenceMappingGenerationAgent(adapter, settings, product_guidance=...)`，注入**现有**开发Harness的 `generation`；不新建调度器，不新增环境变量、API字段或生产开关。调用者选择已固定的短概念任务，候选仅接受question_answer模式；不自动把题目按关键词分类。已有回答诊断路径仍跳过生成。

- `run(inputs)`：返回精确的原 `GenerationOutput` 类型，可直接走原Harness。映射不附到答案、假定、缺口、审核输入或政策中。
- `run_with_diagnostics(inputs)`：开发调用返回 `CandidateResult(output, mapping, report, report_path)`，原答案输出与诊断旁录分开。
- 需要跨运行保留旁录时显式提供既有 `diagnostic_dir`，只允许忽略的 `data/retrieval_local/` 范围。实际输入、候选目录、发送前消息、响应和成功／失败旁录均由现有私有诊断入口保存。不开诊断时不落盘；`run()`不会缓存可变的last_report，开发者应通过专用方法读取旁录或启用私有保存。
- 候选拒绝时抛出原类型错误，开发入口可读取异常的 `candidate_report`；原ModelBudget记录还保存逐请求的安全校验诊断。Harness照原规则停止，不能因为部分答案结构有效就放行给审核，也不会自动换回原生成器再发一次。

本轮测试只用合成适配器；文档不提供连接真实供应商的即跑命令。新付费对照尚未冻结或授权，不能沿用旧批次授权。

## 最小映射契约

一次生成请求同时返回原四个根字段 `answer_units / assumptions / missing_information / evidence_sufficient` 和必需的 `diagnostic_map`，不增加规划调用。原四字段直接复用 `parse_units`，包括严格ID、答案长度和产品模式正文限制；新根契约严格拒绝缺字段、外来字段和错误类型。

`diagnostic_map` 为1—6行，每行仅五个字段：

|字段|校验与含义|
|---|---|
|point|1—240字符的简短必答点建议；不是用户评分要求或权威任务目录|
|unit_indexes|本次answer_units的不同零起始索引；可为空以描述缺口；布尔值、越界、重复均拒绝|
|quote_ids|最多8个不同的本输入依据候选ID；没有依据可为空，不强迫选错ID|
|condition_ids|最多8个不同的现有条件载体ID；其quote_id须同时被本行选中。载体是完整原文范围，不是程序识别出的最小必要条件|
|note|1—400字符，简述依据与所问关系、适用条件或具体缺口；不是长推理记录或支持标签|

复用 [quote_candidates](../../../services/quote_candidates.py) 的whole_fragment候选和 [condition_candidates](../../../services/condition_candidates.py) 的载体绑定。原始证据正文已经在输入中交付一次，新增候选目录只引用对应evidence_id，不重复发送另一份正文。完整片段粒度保守，**不证明条件已识别正确或已写入答案**；[]也不证明没有条件。

输入身份绑定原问题、题设／背景、原要求、完整证据、来源绑定、知识版本、候选版本及产品指导选项。程序分配请求范围ID、point ID、答案单元ID，按原答案组装计算位置；模型选择索引／候选ID，不计算或返回字符位置。依据身份、来源版本与实际文本由程序带回旁录，不补造或替换ID。

映射允许只覆盖部分实际单元。模型仍须在**实际答案**中保留条件，少答、漏问、无据附加及错误关系不因映射合法而变正确。覆盖状态、支持标签、整体正确／通过均不由新映射输出。

## 答案失败与映射失败分别记录

报告版本 `generation-map-attempt-report-v1`。每个请求独立记录envelope、answer、mapping三个结构层的valid／invalid／not_checked及原调用号、是否纠正、output_status。

|情形|处理|
|---|---|
|仅映射失败|answer=valid、mapping=invalid；该次**候选契约无效**，仍计作映射失败，不把答案计为结构失败；不输出部分答案给审核|
|答案失败|answer=invalid；mapping可独立valid或invalid，二者分别记录，不说映射能证明答案正确|
|两者均失败|保留两层invalid；both_invalid单列，不把各分项简单相加成总失败数|
|根层外来字段|即使答案和映射各自有效，envelope仍可invalid；例如模型多声明all_correct，候选仍拒绝|
|JSON／请求未能检查|畸形JSON、重复键、传输失败或取消时，相应层not_checked，不补成答案或映射错误，更不转为证据不足|
|无证据|沿用原确定性无实质回答路径，0次模型调用；映射not_applicable_no_evidence，不充作一次有效候选生成或映射失败|
|存储失败|既有存储错误仍使执行停止；即使模型契约有效，也不宣称候选已完整交付／保存|

`failure_counts`保留mapping_only、answer_invalid、mapping_invalid、both_invalid、envelope_only、unchecked；它们有重叠，不是可相加的互斥总数。`candidate_valid`由程序在整份契约及已请求的记录保存完成后确定，不是模型的语义正确声明。

仍复用原 `structured_request`：一次初始请求，最多一次显式格式纠正，共享原ModelBudget和截止时间。首次映射失败、纠正后有效的两次记录都保留。预算不足不发第二次，传输失败不重试，失败不走其他生成路径；取消中的实际调用归属以原ModelBudget为准，旁录的未完成请求可暂缺调用号，不伪造号码或声称0调用。

## 审核独立性与离线结果

新增 [20项专项检查](../../../tests/test_generation_mapping_v1.py)。在运行中的测试循环内禁止socket连接，所有模型响应均为合成；不创建供应商适配器，不加载.env。专项和相关生成／公共输入／Harness／图差分／政策共 **139项通过，0失败／错误／跳过，34.956秒**。未重跑全套1016项或历史预测回放。

|检查范围|实际证据|
|---|---|
|默认与兼容|原schema3答案解析结果一致；产品候选仍用原严格正文校验；生产schema13和顺序路径默认保留；已有回答模式不调用候选|
|证据与位置|原快照保留所有交付证据、未选中资料、来源绑定与要求；旁录依据及答案位置逐字回切；问题／要求／来源版本变化后旧ID拒绝|
|失败与预算|仅映射失败、答案失败、两者失败、根层错误、JSON未检查分开；一次纠正、预算不足、传输失败、取消、私有存储前／后失败均停止，不放行部分候选|
|实际全文审核|合成答案两句，仅第一句映射；第二句含无据二十年保证。原ModelClaimExtractor服务提取两句，原Harness把两句交给事实及领域审核替身；映射字段和私有note均未进入提取／审核输入|
|隔离与记录|同一候选实例并发开发运行不共享last_report；成功／失败私有旁录均可回查；新增目录不重复证据正文|

上述全文审核检查使用真实提取服务的契约／解析和合成响应、审核替身，证明**实际新增句仍在审核输入内**；没有证明真实模型一定会正确提取或指出该句，也没有新增schema13语义成绩。

首轮15项检查曾14通过、1失败：接线夹具只带了一条来源绑定，而原Harness实际交付两条，导致候选范围ID不匹配而被严格拒绝。补齐夹具后15项通过，随后扩到19项通过，再增加产品模式检查后纳入最终139项。没有放宽校验。首轮失败保留于会话并在[机器记录](results-v1.json)归档为摘要，不伪称保存了当时完整原始测试日志。

另一次回归启动因自动审批额度用尽而未执行；用户要求继续后，通过同一审批机制执行成功，没有绕过审批。完整最终离线日志留忽略 `data/evaluation_local/generation-mapping-v1/offline-checks-v1.txt`，公开仅统计和文件身份。

## 当前结论与停点

**A的开发实现和离线接线完成；是否确实减少条件遗漏、扩大因果及无据附加仍未验证。** 合成响应通过只能证明校验、预算和数据流，不能把旁录丰富或契约成功当作答案更好，也不宣称更快、更便宜。

回退仅对后续新的开发运行继续使用原 `EvidenceGenerationAgent`；生产本来未切换。失败候选记录保留，不自动重发。映射不传审核、不成为评分分母；新增覆盖仍先旁录，不接原政策。

下一步是准备并确认固定证据下的真实生成对照冻结：原／候选同问题、要求、证据和模型设置，用户侧评分要求独立预定，交错顺序，答案出现与审核结束时间分开，结构失败与语义问题、映射单独失败分开；全量计划项、纠正、失败及未执行保留。每组消息、程序与材料身份、预算／超时／停止和新费用授权需在执行前固定。本轮未制作该批材料、未发起真实调用，不自动进入B、修订、UI或生产切换。
