## B语义最小规格：只处理题设—规则—应用

沿用统一设计B，不在本轮增加完整覆盖判断、修订、UI或框架切换。建议单独候选协议`public-review-premise-boundary-v1-dev`，不能冒称生产schema13已支持，也不复用独立v7评测器作为生产实现。

1. **任务题设由当前输入独立提供。** 程序对明确给定的假设登记premise_id、stipulated/unverified_report、question或user_context字段、任务/内容哈希、版本及原文范围。程序计算位置；模型只选已有ID。题设类型需显式声明，不能靠关键词或模型把任意用户现场报告升级成可信假设。生成答案、assumptions、映射、审核理由均不能成为登记真值。
2. **模型区分实际断言对象。** 文献定义/规则、题设重述、规则应用、现实设备/现场断言及uncertain分开。对象分类仍是模型判断，程序身份校验不证明分类正确；对混合句按实际命题/组件拆分，保留否定、条件、阈值、数量、许可强度。不能自动把整句转成“用户提供了X”。
3. **依据关系分别限制。** 题设引用只证明当前输入给定了什么。文献规则仍选正文quote ID；应用结论选规则正文与适用题设，并解释阈值/例外/许可如何连接。快照、元数据、答案原句都不能单独证明技术规则或现场状态。不把题设伪装成Evidence正文以适配旧解析器。
4. **严格拒绝与合法未知分开。** 非法/跨任务ID、错版本、漏字段、缺理由仍是契约失败，有限纠正耗尽保留部分结果；无规则正文是证据不足，来源明确相反才是矛盾；对象无法分清可not_assessable并说明，不补造依据。现实设备断言缺测量/运行资料，应说明对应缺口，不能要求普通定义题现场验真。

例如“按题设概率60%，规则允许省略”：题设重述绑定给定60%；规则绑定“60%及以上时may省略”；应用结论联合两者，支持范围仅为此假设场景，不意味着真实天气概率已核实。一般规则、题设与应用可以出现在同一句，不强制三句输出；组件之间仍需可检查的关系，支持判断不与覆盖槽一一对应。

输入问答与已有回答诊断复用同一题设目录与公共审核准备阶段。前者保留完整实际生成快照，后者只绑定实际已交付输入，缺原引用或生成快照就明确缺失，不能补造。新增题设引用将是候选新契约类型，**现有TypedBasis/严格解析器尚不接受它**；在完成版本化解析与输入接线前，不启用真实候选或改变政策。新增覆盖仍仅旁录，不因covered放行。

最小接线范围：扩展公共输入的题设载体 → 提取器显式取得独立目录 → 候选解析器支持题设及应用组合 → 公共审核准备与原审核调用中传递。复用现有请求次数，不另建Harness/Agent调度器；不接生产工厂、不改历史数据、不改变原引用证据范围。新增类型需完整验证核心类型、ID/版本及原文定位，不能只在消息里加一句说明。

**下次语义实现的停止条件：** 需要把快照放行技术正文、需要把生成自列映射当真值、缺题设时靠推测补全、必须改变原政策才可通过，任一情况先停。无法保留混合断言/真实现场义务也不接线。此处是明确实现边界，不代表已经完成语义修复。

## 独立工程修复：只按本事实调用归属计算纠正

已增加开发参数`correction_accounting="invocation_scoped_v1"`，仅schema13允许；构造默认仍为`shared_slice_v1`，原生产工厂、配置、提示、解析、消息内容与政策不变。它不是schema14或新语义能力。

新模式按**invocation_id＋component＋answer_version＋prompt_version**限定本次事实阶段记录，独立事实和全部原引用仍共享一次格式纠正。事实输出的model_records同样按归属筛选，不混入另一同提示事实调用。无Harness归属的直接开发调用由程序临时绑定唯一ID，退出恢复上下文；正常Harness已有归属原样沿用。新增current_model_invocation只读标识，不涉及凭据。

共享总预算没有分割或提高，两个Agent实际发生的调用都计入原总数；恢复本来应有的事实纠正机会可能使实际调用比错误旧行为多一次，不称节省费用。取消仍保留请求记录，不自动重试；失败保留同伴结果与原停止机制。

离线合成复现：独立事实有效返回前，领域先完成一次纠正，接着原引用初始格式错误。旧模式只有2个事实请求，误以为事实已用纠正，引用未完成；新模式给该引用唯一纠正，3个事实请求完成。含领域两请求，总调用由4变5；共享预算限定4时仍拒绝第5次、保留不完整状态。相同提示/相同component但不同invocation也不会串账。两模式前两个初始请求逐字相同，仅新增合法纠正机会。

## 分开验收，不能互相顶替

下列均为教学/合成场景，尚未作为新真实测评执行，不设准确率门槛。它们限定下一次语义实现应覆盖的行为，不修改旧参考。

|场景|期望边界|
|---|---|
|假定P=60%，规则P≥60%可省略，答允许但非必须|题设、正文规则及应用分别有对应依据，仅支持假设场景|
|同规则，答恰60%必须省略|已回应许可方面；应用/许可语义错误由支持性处理，不机械扣覆盖|
|假定P=59%，答达到60%阈值|忠实保留错误断言；核对实际题设与规则，不把回答自身的60%当真值|
|只说“题设给定60%”，没有规则正文|题设重述可核对；不能因此确认省略规则或应用结论|
|只有≥60%的一般规则，没应用题设|一般规则有据不等于完成显式应用要求；审核理由不能补出回答|
|假定样品属于类别K，规则K需步骤T|不要求现场重测类别；应用是否有效仍由规则、条件及模型判断核对|
|“现场实测就是60%，所以安全”无记录|不能用题设/快照确认真实测量、安全或工程充分性|
|条件未保留、仅支持局部的混合句|分别记录各断言，不能以支持子句替全句通过；不挑有利拆分|
|题设ID来自另一任务或文本改过|严格拒绝，不替换ID，不凭相似文字修复身份|
|请求超时/JSON最终失败/存储失败|执行未完成；不投影成语义证据不足或模型事实矛盾|

语义实现将单独验证原文身份、拆分/混合、规则和前提联合关系、缺现场记录及两输入模式一致性；计数只用并发替身、预算、取消及归属测试验收。两项都不把“程序检查通过”说成真实模型已能正确分类。
