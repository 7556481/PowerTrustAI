## 依赖与时间精度

prepare_review先完成事实检索（含原预检主体补检）、领域检索，再构造v_input/d_input；review_pair随后并行两个角色。事实catalog、baseline wire、原引用分组、条件候选/transport构造均在事实Agent内部。独立事实请求和每条原引用初检均不依赖彼此模型输出，最早可在同一个事实输入对象具备后准备；独立纠正依赖其初检响应/诊断；引用纠正还必须等待全部更早逻辑项的纠正资格确定。预算不足时原回退串行规则保留。原引用引用的是生成快照，不可借独立新证据改绑定。

输入齐备时刻没有独立打点：初检统一给出[最后审核检索完成观测，首次事实准入]区间。纠正给出[前置初检结算观测，纠正准入]区间；结算mtime是保存usage的观测，不是精确响应/解析结束，真实齐备位置未知。模型事件集中记录，不能用event减duration伪造HTTP起点。阶段端点为实际event，起点由毫秒duration推导；journal准入/首次结算提供请求包络，存在本地处理/文件观测误差。原始ledger-timeline由原预算journal/mtime派生，输入SHA留私有bound.json。

领域审核已经并行，因此终态使用max(事实完成,领域完成)+原merge/Store尾部，不相加两个角色。各请求持续时间只用于独立因果链，不能把请求节省直接相加当用户收益。初稿边界为generation阶段完成，不是点击提交或浏览器首绘。Q3/Q7本来事实合同失败，不能把它们的终态叫完整审核通过。

为了得到足够宽松的否决上界，本计算甚至把全部原引用请求及其解析/间隔都归零，独立请求构造、纠正间隙也归零，只保留历史独立初检与其纠正的较短观测耗时和既有领域阶段完成；末端merge/存储尾部保持。这个假想优于最多两路的实际调度，也优于仅提前首条原引用。Q10没有原引用模型请求，因此调度节省为0。新并发下HTTP/限流/响应/纠正可能变化，记录不能给出正的保证节省，故逐题下界是0。

不把事实检索后到领域检索后的等待算进本候选：当前代码尚未构造v_input，提前跨过prepare_review并和检索交错是另一种Harness检索—审核流水线改动，不是复用事实双通道的本轮初检调度。也不将引用正文在初稿完成时已存在等同于当前完整审核请求已可发送。若改变该阶段边界，应另行冻结估算，不能套用本表。
