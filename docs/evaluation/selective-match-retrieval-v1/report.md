## 唯一候选及记账

`execution_profile='selective_match_v1'` 默认关闭，复用既有 Retriever、Evidence、邻接和 Harness，未另建调度器。仅去除程序拥有的精确尾缀和输出字数格式；保留其余分词，包括主体、实体、数值、单位、否定和条件。所有保留词实际进入各次 MATCH 的评分 OR；追加主题约束也进入 SQLite BM25，评分语义明确不同于生产，不宣称分数等价。

确定性规则优先已有电气词典概念，再取输入顺序中的名词/实体，最多四组；别名只在组内 OR。首阶段对所选主题组求交，超过两组时最多再用“首组+第二组”和“首组+其余组 OR”两种选择性放宽。最多三次排名 SQL；一或两组不放宽，没有合适主题则未知。无 DF 自适应，无最终无条件宽 OR 回退，也不把全部输入词机械 AND。

每阶段最多取原 K，完整解析、去重并记录词面覆盖；K 填满不足以停止，还需所选主题和限定词的词面覆盖。此判断不代表语义充分。最终采用新增词面覆盖优先、再按阶段及阶段内排名的确定性选择，不直接比较不同 MATCH 的 BM25。每个原始局部分数保留其阶段标记，合并版本 `selective-match-stage-priority-v1`。语义目标交付映射由后续逐原文复核单独记录。

每次排名均消耗原调用预算；所有中间唯一片段正文消耗原每调用/总字符预算，最终交付不重复扣同一正文，邻接另扣。预算不足停止，不补 SQL；验证使用紧邻查询证书且重验正文身份，缺失证书拒绝无预算排名重放。取消时中断自己的 SQLite 连接并等物理工作结束，才释放槽位；不触碰用户进程。原 K、邻接、来源版本和 deadline 不增加。

## 后端路线边界

本轮临时 `fts5vocab` 只读主库，按词等值限定查询，至多24个去重 DF、各30秒；至多6个完整表达式消融 COUNT、各60秒，超时未知不重试。`doc` 表示含词行数，`cnt` 为出现总次数，并非业务文档数。[SQLite 官方说明](https://www.sqlite.org/fts5.html#the_fts5vocab_virtual_table_module)

`detail=none` 会舍弃位置并限制短语/NEAR，部分位置 API 需重新读正文或在 contentless 索引不可用，不能据索引较小承诺 BM25 更快或相等。[SQLite detail 说明](https://www.sqlite.org/fts5.html#the_detail_option) 分主题路由有漏召回风险，分片局部 BM25 不能未经设计直接混合。Meilisearch 默认采用一组有顺序的相关性规则，不能称为现成 BM25 替代。[官方排序规则](https://www.meilisearch.com/docs/capabilities/full_text_search/relevancy/ranking_rules)

如需下一阶段后端原型，Tantivy 可以作为待检验选项；必须先固定同一小子集、中文分词及词典、来源ID/版本/区间、位置与正文存储、K/同分规则及公平原 SQL 基线，测构建时间、峰值/增量磁盘、内存和完整正文读取。全库磁盘及构建时间仍未知，不能将小子集结果外推全库；本轮没有安装、构建或启动后端。[Tantivy 官方库文档](https://docs.rs/tantivy/latest/tantivy/)
