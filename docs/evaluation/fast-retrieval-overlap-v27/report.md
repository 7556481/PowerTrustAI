## 一套资产的可行性：小样本通过，不等于全库交付通过

当前双库实验路径仍需要：70.85GB SQLite（全文/来源身份/字符区间/邻接）、90片原生索引（候选/DF）、约6GB映射（封存身份/核验）、53.68GB spool（候选TF及terms_sha）。不能将这套组合当最终交付，生产仍用原SQLite。

新增小样本把每个fragment的完整Evidence及原身份/版本/范围/邻接ID存入原生stored bytes，把既有terms存为indexed+stored并保留position；原生索引直接提供词DF，stored terms计算TF并核验旧terms_sha；fragment_id的raw索引负责原文/邻接查找。无需另建全量SQLite索引、外部mapping或运行时spool。历史evidence_id、fragment_id、source_version、knowledge_version和原范围保持原值，新资产指纹单独版本化，不能静默重算历史引用ID。

最终样本为10个完整来源文档/293片段，原生文件606402字节；实际在验证进程阻断所有sqlite3.connect、旧retrieval路径和网络，先证实两个旧库连接均失败，再完成同一查询AST/IDF-TF/选择逻辑的3根检索、2段邻接/2095字，3个旧引用完整payload比对通过，多词reactive power短语也通过。没有挪动/删改旧SQLite或spool实体。初样本13片未覆盖测试查询、注释字典还原失败均保留；静态检查发现TF-only字段不足以维持原短语合同，随后保留原position并实际验证短语。只修夹具/接口与保留原position，不轮换检索选择规则。

未来文件清单：asset/group.json及每片验收/hash清单；asset/shards/NNN原生索引（terms/位置/全文payload/身份/范围/邻接键）；可选的少量原始PDF/原始记录附件用于整份文档查看；用户runs.sqlite3/预算及诊断独立保留。旧历史Store本来存有原文对象；重审时由同一legacy知识版本映射到新资产，按完整字段/hash回查，缺失或版本不符必须拒绝，不能用近似段替换。全库迁移仍须逐成员/全文/边界/邻接等价和历史引用回归，再以单套形态完成产品验收。

按这个偏向历史PDF、非全库随机样本线性外推约50.96GB，**不作为容量承诺或统计置信区间**。工程先按50—150GB整套资产、再加当前约0.19GB用户Store/诊断/运行环境规划；中文全量分布、压缩与positions开销尚未实测，可能超出该规划。若逐25万成员分片、只保留单writer并原子封存，除最终目标外暂按5—10GB单片合并/缓冲空间预留，迁移验收前旧资产仍需同时保留；这些是构建计划而非峰值实测。本轮没有启动全库重建，也不能承诺磁盘一定变小。

## 可操作结论与归档

结束这一冻结选择候选，不付费、不提出“首稿和终态都更快”、不建议正式启用或全库迁移。速度上界有空间，实际关键查询仍有未知，且选择未通过已知必要依据保留；不能用1.87倍或已发布29.20%弥补。单套资产的小样本运行路径可行，但组合尚未取得双库产品门槛证据，所以结论没有升级为“值得做全库单库迁移”。

新增5项离线测试覆盖整段预算/冲突ID、非ID特判、宽池与原邻接接线、原引用无SQLite回查；公开CI无原生依赖时最后一项显式skip。实际输入/响应/完整原文、56回放结果、172个历史边界请求及4个ISO控制请求、898秒资产核对、单套样本和构造失败记录在data/runtime_local/fast-overlap-v27。public summary.json只含脱敏统计与null的新产品等待结果。最终提交/推送/CI回执另存closeout.json。
