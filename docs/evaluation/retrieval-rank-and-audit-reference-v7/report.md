## A：固定三请求，显式LIMIT无稳定收益

先读[SQLite官方FTS5 §5.2](https://www.sqlite.org/fts5.html#sorting_by_auxiliary_function_results)：rank默认对应无额外权重的bm25，但可改映射；官方指出rank排序配合提前停止或LIMIT可能更快，这不是本库达标保证。实际Python SQLite3.45.3、ENABLE_FTS5；corpus_fts_config只有version=4，无rank覆盖，确认本库为默认bm25。小型双列索引的非默认权重测试说明不能无条件假设相同。

旧sql_compare.py确实使用ORDER BY rank，无rowid次键、无SELECT bm25，且显式每查询映射bm25()；它读完第K名边界，再排序rowid。无SQL LIMIT，超过4096已选项会重新执行原SQL。其计时含游标读取/Python排序和可能的回退；旧日志只存最终3行及耗时/哈希，没有examined或fallback标志，**无法证明当时是否触发4096回退**。旧表达式配置也较早，本轮不重放旧查询或以“曾更慢”代替新证据。

冻结最近三组诊断的各首条事实请求：47cd0746最慢、1d31a0e2次慢、f7cf4ad6较快对照，完整query/表达式、K=3、知识身份、scenario、邻接选项和110秒原阶段预算及输入SHA留私有freeze。执行前及每槽确认无queued/running，起初8765无监听health；未操作用户进程。无排名缓存、无清OS缓存。只读70,847,647,744字节原库；封印204.997秒单列。封印元数据计8,630,479条规范记录、24,620,273片段、5,705,698重复记录、73分片；未新增全表扫描、COUNT全库、索引、数据库复制或VACUUM。

原SQL使用bm25 AS score、ORDER BY score,rowid LIMIT K；诊断使用rank AS score、ORDER BY rank LIMIT K，无稳定同分保证。3轮路径顺序事前交替冻结，全部18次排名完成；3次MATCH COUNT各只一次、均在60秒内完成，测试区间353.330秒（含COUNT、空闲检查和保存/计划开销），低于30分钟；每次排名原110秒时限保持，progress handler及定时interrupt均有界，未补槽。
