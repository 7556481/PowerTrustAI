## S2根因及 v3 的限制

逐字只读v4/v5共3份S2事实响应及其实际请求、引用和缺陷边界：源文把临界负荷水平下协调的重要性、联合研究的可能需要、带宽外DP纠正，以及补偿/故障情景的考虑要求分开。v4先出现not_entailed却supported，有限纠正后边界扩展到相邻正确要求，Revision超时；v5自由概括来源关系时淡化其条件性，最终认可原稿。实际原文已交付且引用身份合法，不能把问题归因缺源或读取投影。

v3只改变同一审核内的关系依据：现有relation_check.source_relation不再自由中文概括，而须逐字复制本单元所选合法quote内唯一连续原文；沿用quote/locator对象，未加裁判或逐句调用。无可定位依据则null/unknown及不足或不可评估，不授权修订。程序仅检查字面绑定与状态一致性；模型仍负责完整主体、条件和模态解释，混合单元须只修新增义务/排除并保留真义务。无案例ID、LPF或关键词特判。

真实批次暴露新合同负担：模型多次改写原文换行/空格，或加省略号拼接分散段落。45个实际事实响应单元的只读机械归类：17处仅空白改变、16处逐字匹配、5处显式省略/拼接、7处null/其他；这是有重复纠正的响应单元计数，非45个独立案例或语义准确率。未用归一化、自动补引用、放宽定位或静默修响应换过关。
