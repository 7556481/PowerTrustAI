现有百万spool是仿射随机行业前缀，不是本完整顺序的前缀。只能按ID及正文/terms hash匹配后复用，不可直接接在其后续写全量；最多复用约4.06%行业预分词输入，仍有重排/校验成本。674文献输入也须逐项同字段校验后复用。旧48k、684k失败目录不作恢复起点。

## 阶段与恢复协议

1. 准备阶段使用PreparationStage和InputSpool：源/词典/查询/schema/代码身份固定，SQLite事务提交有序batch，重开后流式重算prefix hash；未提交事务回滚。准备、writer、验收、发布共用同一budget.json，总额不可被新参数覆盖。
2. 同一构建根用OS文件锁独占，单writer每段生命周期；每batch先持久化prepared journal（起止position、signed ID、fid、正文/terms hash及payload hash），再T commit，后映射事务，最后checkpoint及删除journal。不是每1000条重开writer。
3. 重启前独立监督先排除已核验PID+创建时间的旧worker；无法确认在途进程则禁止新writer。恢复核对所有身份、已提交prefix hash、原生全部ID和映射。T未提交→仅可重供相同冻结batch；T已提交而映射落后→校验原生ID后只补映射，不重add；映射超前、未登记commit、不明边界或hash变化→隔离失败，不续写。正常暂停已commit检查点与失败目录不可混同。
4. 正常停段wait_merging_threads一次并释放writer；下一段新监督目录、原构建根恢复。原错误先保存，清理错误另存；原生commit/merge不能强行Python取消，沿既有v3独立监督的grace与PID/创建时间保护，仅停止本次隔离进程树并标INVALID，不能当正常检查点恢复。
5. 每段绝对期限≤4小时，包含暂停、休眠、观测空窗；恢复先检查过期。总预算持久化累计，异常active interval保守计入失联时间，不能重置。PreparationStage/CheckpointBuild接checkpoint回调到既有Guard.check；独立supervise仍负责资源、用户忙、heartbeat/gap及强制退出。合成恢复协议已测，完整规模的组合驱动尚未运行。
6. 完成后新进程只读逐DocAddress遍历全部无删除segment，一次一个ID，SQLite TEMP UNIQUE完整核对集合/重复/缺失及全部映射hash，绑定输入prefix和source seal。terms不复制为可读正文；证明是冻结输入hash、按序add与提交journal及不可变原生文件hash的链条，不能称独立反解了每个倒排词项。原文由现有来源读取层回查。
7. 验收proof绑定全部原生文件bytes/SHA；同盘临时目录rename到唯一版本目录，不覆盖既有版本。最后才原子发布经过重新hash核验的manifest。rename后崩溃无manifest，产品拒绝加载；finalize_publish须重新校验身份/文件。完整性通过仅成为技术可读状态；quality_gate仍需独立批准。部分样本只在explicit isolated模式可读，永不替代生产全库。

没有FTS新库双写：原生产FTS只读，独立mapping是唯一派生提交映射；不复制70GB源库。历史FTS对照索引仍保存，完整阶段不能偷偷再建一套全量FTS。

## 预先固定的质量门槛

先冻结，不能建完后挑成功题。沿原12个问题及原AST/K/证据/邻接预算，FTS与完整T分别运行同一冻结计划，保留全部原文及差异，模型0。来源身份错误、未解释的查询类型变化或必要反证/条件丢失阻止服务发布。

固定专项包括674集Q10：交付须保留高压越限前提、两类并联设备动作，以及1.05pu和TO确认设备额定例外；Q4不能把原有组织背景替换成人事新闻后称保护成功；Q12额外偏题替换需消除或明确不能进入默认发布；Q2两条近重复占2/3应报告有效信息覆盖，不能凭ID不同算多样性。逐项人工复核正文，AI辅助、用户监督，非专家金标准。查不到的语义结论写未知。命中数相等不算质量通过。

本轮没有选择新的重排、去重或上下文扩展机制，K及证据预算未扩大。这些风险仍未解决，manifest固定blocked_known_coverage_risks。完整索引可用于离线质量研究，但不能因建库成功变成默认产品配置。不得沿用旧5.220倍作为新适配器或全量性能成绩。

## 资源与预算建议（下一轮须明确授权）

|阶段|规划范围与依据|停止阈值|

|总体|上述约76–142GiB，160GiB含余量；96GiB不能保证足够|当前D盘约797GiB可用，仍须开始时重查|

本机约8GiB物理内存，本轮只读观测约1.82GiB可用；未来树上限=min(开始可用/2,1GiB)，不足合理128MB writer加Python/监督/merge余量时不启动。工作线程≤2，建议沿已验证单worker128MB heap；整个树及系统提交/可用内存均监测，不能把writer heap当树总内存。低优先级；用户服务忙或健康状态未知则安全检查点暂停，不修改睡眠或安全软件。

时间仅作预算区间：输入准备约24–60小时；writer含merge约3–12小时；完整验收约3–12小时；性能/质量归档约1–4小时。依据是既有750k准备2609秒、百万writer419.621秒/验收267.324秒，但这些含FTS/抽样访问且非全量顺序生产者，不能线性承诺完工。建议未来总累计上限96小时，每段≤4小时，含暂停和空窗，超额只归档停止，不自动续额。可复用spool降低部分准备，不能减少未覆盖输入的工作。

服务加载成本包括70GB源封印一次、T所有文件hash一次（量级12–22GiB）、mmap及每请求隔离进程加载。不能保证全量RSS仍为百万峰值；服务需独立负载准入，预算仍≤1GiB树且不挤占现有服务。当前每查询spawn的启动成本不包含在旧内核倍数中，产品延迟另记。源封印不是每题全库扫描。
