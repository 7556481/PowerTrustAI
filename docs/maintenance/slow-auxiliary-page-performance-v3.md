## 先复现再修改

真实app.js的旧6+13组保障保留。新增确定性Promise/轮询时钟基线4组全部失败：一个或三个辅助挂起时主结果已可见但轮询计时器数为0；反馈保存回读与原reviews GET最大在途2；终态NLI pending时trace/reviews跟着重读3次。没有用墙钟sleep，也没有把理论45秒称实测。修前源码及slow-before.log在忽略目录data/maintenance_local/slow-auxiliary-v3。

主state/result仍顺序组成一个无重叠周期；之后启动NLI/trace/reviews而不await它们，原唯一1800ms计时器可继续下一轮主读取。端点slot记录连接epoch、run、请求revision、在途身份、局部暂停及终态状态；每端点最多1在途，手动刷新合并成最多1次待刷新。核心读并发上限为主周期1＋辅助3（不含用户另外点击历史/证据等独立GET）；15秒请求期限不降低，POST不重试、不宣称取消后端写入。切换/断连/重连/离页取消失效GET，所有成功/错误/finally校验归属。

辅助失败仅局部清旧详情并暂停该项；主失败停止并取消余下GET，当前401断连，旧连接401不能注销新连接。运行期发出的慢详情在终态晚到后至多补一次最终读取；终态trace/reviews收敛后不自动重取。NLI pending仍用同一主轮询源继续观察，最多10次终态诊断检查，仍pending则明确提示手动恢复，不永久后台轮询。反馈保存推进reviews revision，使旧列表不能盖住新反馈，回读复用同一slot，不另开GET。前两轮草稿/版本/finding重核、未知提交保留等保障保持。

最终12组慢辅助/渲染探针、旧19组、原POST/安全探针通过。断言包括辅助仍挂起时下一主读取已显示finished、每端点最大在途1、虚拟15秒超时、手动恢复、旧成功/失败/401、主失败、离页/重连、单计时器、NLI十次停止、反馈回读归属及内容变化/失败后恢复。没有真实浏览器网络拦截能力，慢挂起故障只在实际JS探针验证；真实浏览器验证正常网络，不混称故障注入。

## 实际浏览器成本与局部优化
