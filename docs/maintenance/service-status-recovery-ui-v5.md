## 状态对应操作

|最近确认状态|新任务|已有记录与恢复动作|
|---|---|---|
|ready且明确可接单|允许，发送前再GET核查|正常查询；实际POST仍可能503/429|
|旧health无生命周期但ready/configuration_ready=true|兼容允许，明确缺字段|后端最终接单保障保留|
|未知或网络不可达|禁用，未知不当作ready|已读结果/输入保留，可尝试历史GET，实际可读性不保证|
|生命周期故障/closing/配置未就绪/存储故障|分别解释并禁用|历史、版本、证据按实际GET；存储允许时可追加反馈|
|队列满|禁用，不自动重试|手动检查恢复能力，不重发原请求|
|401|连接失效|公共health成功不恢复鉴权；需原连接流程|

“重新检查服务”复用连接区，只GET /health，同一时刻一个在途检查，无新增计时器、不启动服务、不引导会话、不提交任务。失败保留已读结果和草稿；成功也不能清除未知POST锁。旧epoch、请求身份与服务状态修订校验阻止较早health覆盖新故障、恢复错误提交能力或注销较新连接。错误只展示受控分类，不回显原始异常/堆栈/凭据。

自动查询仍复用既有单主调度器与每端点单在途slot。明确pending_terminal_status=interrupted且persistence_confirmed=false才结束按queued/running持续主查询；读取已有主结果及可用辅助信息，终态辅助失败/NLI pending仍按原机制及10次上限收敛。仅service_fault_code而实际running仍继续。主运行状态以state接口为准，不能用早期result投影提早停止。实现中旧探针曾检出该回归，已修正并重过20/12组；日志保留。手动查询原记录仍可用。
