# 历史原型与新系统判断边界

旧目录 `power-system-hallucination-risk-assessor` 保留为历史研究基线，不修改。
它不是新项目必须兼容的算法规范。旧分数、结论、六维设计、权重、阈值、
默认参考文本、关键词规则均不得未经审查成为新系统的生产判断依据。
不要求维持旧分数/旧结论，不强求总体风险分数。

## 当前实际依赖检查

检查 `agents`、`core`、`harness`、`services`、`rag`、`model_adapter` 的导入、
动态加载/路径设置、判断函数与默认常量引用，并对照旧 `app.py` 的
DEFAULT_REFERENCE_BY_SCENARIO、DEFAULT_NUMERIC_CONSTRAINTS、DEFAULT_SAFETY_RULES、
DEFAULT_DOMAIN_TERMS、评分与加权逻辑。

**新运行链路未发现对旧算法模块、旧配置或旧默认参考文本的依赖，未发现复制这些
默认假设来作新判断。没有此类依赖需要重构。** 这里是源代码与调用路径检查的结果，
不是对两个系统所有历史设计思想完全无关联的证明。

当前链路是 CLI → OfflineHarness → Retriever/ModelClient → Generation/ClaimExtractor/
Evidence Verification。事实核验记录四种局部状态、证据和限定，不计算旧风险分数。
BM25 分词和术语扩展仅用于检索排序，不是旧领域关键词的事实/安全打分。
FakeConfig 默认回答及支持状态明确是 synthetic_fixture 测试替身，不是生产知识或默认真值。
`agents/generation.py` 的 legacy citation schema 指旧数字引用接口兼容，不指历史项目算法。
Harness 的 `offline-policy-v1` 是新离线测试策略，不是经验证的真实工程审核逻辑；
真实领域审核仍未实现，真实局部审核不能宣称整体 pass。

## 后续迁移逐项决策

| 历史能力 | 决策 | 理由与前提 |
| --- | --- | --- |
| 通用文件读取、导出、配置、日志等工具能力 | 保留（逐项审查后） | 先验证类型、错误处理与凭据保护；不携带默认参考文本或旧评分副作用 |
| 旧 UI、结果展示与场景配置 | 改写 | 展示证据定位、审核依据、适用范围、执行失败，不能把模拟结论包装成真实审核 |
| 语义相似度、参考一致性及事实可靠性评分 | 替换 | 使用主张级、独立证据、原引用分别核验；相似度不是语义支持 |
| 数值范围和运行安全/关键词规则 | 替换 | 重新设计可追溯工程前提与约束、版本/地区适用性，需要领域审查与验证 |
| 六维分数、权重、阈值和总体风险分数 | 弃用为生产默认 | 原研究参数不是新系统校准结果；原研究结果仍留历史基线 |
| 默认参考文本及缺省知识回退 | 弃用为生产证据 | 未检索到必须显式不足，不能补入默认文本伪装官方依据 |
| 旧关键词启发式判断 | 弃用为生产事实依据 | 可保留历史实验对照；不能凭命中词宣布支持或工程安全 |
| 历史样例与测试结果 | 保留为开发/对照资料 | 标明历史来源与局限，不作为新系统独立验收或必须复现的真值 |

后续每个实际迁移项都记录“保留、改写、替换、弃用”的理由、来源与验证方法。
优先保留通用工具能力，事实支持和工程审核逻辑重新设计。
